# Zorya Classifier: руководство

Zorya Classifier — библиотека для Node.js и TypeScript, которая помогает приложению принимать решения по тексту и изображениям. Вы задаёте допустимые классы или описываете искомый объект, библиотека обращается к Jev 1.14 через OpenRouter/TypeSafe и возвращает структурированный результат. Код распространяется по MIT; веса модели в поставку не входят, запросы оплачиваются отдельно.

Это самостоятельная библиотека: ей не нужны Zorya Games, Electron, база данных или игровой процесс. Её можно встроить в сервер, бота, инструмент обработки фотографий или собственный HTTP-сервис. Готовый постоянно работающий HTTP-сервер в пакет не входит.

## Что умеет

| Задача                                                     | API                                 | Результат                                                                         |
| ---------------------------------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------- |
| Распределить обращения по отделам, определить намерение    | `classify` с текстом                | Один из заданных вами классов и баллы всех вариантов                              |
| Проверить наличие объекта или выбрать категорию фотографии | `classify` с изображением           | Один из заданных классов                                                          |
| Оценить изображение с текстовым условием                   | `classify` с текстом и изображением | Класс с учётом обоих входов                                                       |
| Найти примерную область предмета, значка или указателя     | `locate`                            | Ячейка в координатах исходного изображения либо явная неопределённость/отсутствие |

`classify` делает один запрос Choice. `locate` делает до трёх последовательных запросов: крупная сетка → уточнение в четырёх выбранных областях → сравнение четырёх увеличенных кандидатов. Проверки присутствия входят в те же запросы. Модель выбирает варианты, а координаты вычисляет код.

Библиотека не генерирует описание сцены и не ищет все экземпляры предмета: если подходящих объектов несколько, `locate` возвращает один кандидат. Выбранная ячейка может содержать только часть объекта; это не маска сегментации, не точная рамка и не доказанный центр. Дополнительный алгоритм уточнения можно подключить через `RefinementPort`.

## Установка и ключ

Нужен Node.js 22.12 или новее. Windows и Linux проверены; macOS отдельно не проверялась. Зависимости исполнения — Zod и Sharp, включая подходящий платформе нативный модуль Sharp.

Пакет подготовлен к публикации, но ещё не опубликован. Сейчас установите полученный архив в своём проекте:

```sh
npm install ./zorya-classifier-0.1.0.tgz
```

Скопируйте пример конфигурации в локальный `.env` и заполните значение `OPENROUTER_API_KEY` своим ключом. В репозитории `.env` исключён из Git; в своём проекте тоже добавьте это исключение. Не помещайте ключ в браузерный React-код, приложение клиента или публичный репозиторий. Вызовы модели выполняйте на доверенном сервере.

Создайте `example.mjs` и запустите:

```sh
node --env-file=.env example.mjs
```

Эта команда работает и в PowerShell, и в Linux shell. Вместо файла можно передать переменную окружения средствами вашего сервера/менеджера секретов. Библиотека сама `.env` не читает; флаг обрабатывает Node.js. Ключ требуется только реальному адаптеру; обычные тесты работают без него.

## Первый пример: классификация текста

Полный файл `example.mjs`:

```js
import { createClassifier } from 'zorya-classifier'
import { createOpenRouterJev } from 'zorya-classifier/openrouter'

const apiKey = process.env.OPENROUTER_API_KEY
if (!apiKey) throw new Error('Заполните OPENROUTER_API_KEY')

const client = createClassifier({
  decision: createOpenRouterJev({ apiKey }),
})

try {
  const result = await client.classify({
    input: 'Заказ ещё не приехал. Где посмотреть доставку?',
    classes: [
      { id: 'delivery', description: 'Вопрос о доставке или отслеживании заказа' },
      { id: 'refund', description: 'Просьба вернуть деньги или товар' },
      { id: 'other', description: 'Любое другое обращение, не относящееся к доставке и возврату' },
    ],
  })
  console.log(result.choice)
  console.log(result.probabilities)
  console.log(result.metadata)
} finally {
  await client.dispose()
}
```

Передавайте от 2 до 255 классов с уникальными `id`. Описывайте различия между ними явно. Если ни один предметный класс может не подойти, добавьте `other` или `none` с точным условием выбора: скрытого универсального класса «не знаю» здесь нет.

`choice` — вариант с максимальным баллом. `nativeChoice` сохраняет выбор провайдера, `tied` — варианты с одинаковым максимумом. При равенстве библиотека выбирает первый из них в исходном порядке. Баллы распределены между всеми вариантами: низкий максимум сам по себе не повод отклонять результат. Общего порога `0.8` нет. `confidence`, если провайдер его вернул, не является гарантией правильности.

## Классификация изображения

Внутри того же `try` можно передать изображение и дополнительный текст. Добавьте `readFile` к импортам:

```js
import { readFile } from 'node:fs/promises'

const result = await client.classify({
  input: {
    image: await readFile('photo.jpg'),
    text: 'Есть ли на фотографии велосипед, включая частично видимый?',
  },
  classes: [
    { id: 'present', description: 'На изображении виден хотя бы один велосипед' },
    { id: 'absent', description: 'На изображении нет видимого велосипеда' },
  ],
})
```

Для одной картинки поле `text` можно опустить. Принимаются `Uint8Array` и `Buffer` с одним PNG/JPEG/WebP: до 16 MiB и 16 777 216 декодированных пикселей. Ссылки на изображения публичный API не загружает — скачивание, права доступа и ограничения внешних URL остаются у вызывающего приложения.

## Поиск объекта и координаты

Также внутри `try`:

```js
const result = await client.locate({
  image: await readFile('photo.jpg'),
  target: 'красный рюкзак на стуле',
  exclusions: ['сумка на полу'],
})

if (result.status === 'located') {
  console.log(result.region) // left, top, width, height: пиксели
  console.log(result.normalizedRegion) // те же поля в долях размеров изображения
  console.log(result.metadata.image) // размеры и система координат
} else {
  console.log(result.status, result.reason)
}
```

Начало координат — левый верхний угол изображения после применения его EXIF-ориентации. X растёт вправо, Y вниз. `region` включает левую/верхнюю границы и не включает правую/нижнюю. Для экранного оверлея сначала учитывайте ориентацию, масштаб отображения и возможные поля вокруг картинки. Не переносите координаты на следующий кадр без проверки: библиотека не отслеживает объект во времени.

`roi: { left, top, width, height }` ограничивает поиск прямоугольником в целых пикселях того же ориентированного исходника. Координаты ответа остаются относительно всего исходника, а не относительно обрезанного фрагмента. Указывайте ROI только если он находится внутри реальных размеров изображения.

| Статус                       | Что означает                                                                        | Как обрабатывать                                                                            |
| ---------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `located`                    | Выбран кандидат в сетке                                                             | Показать область с учётом вероятностного характера результата                               |
| `not-found`                  | Проверка присутствия отвергла объект в анализируемой области                        | Не переносить этот вывод на область за пределами ROI                                        |
| `unknown`                    | Неуверенность, противоречие, отсутствие цели среди кандидатов или невозможная сетка | Уточнить цель, взять более подходящее изображение или вернуть пользователю неопределённость |
| Исключение `ClassifierError` | Ошибка входа, сети, протокола, бюджета или жизненного цикла                         | Обработать код ошибки; не показывать её как отсутствие объекта                              |

Небольшие значки, перекрытия, похожие предметы и сложные карты требуют собственной проверки на ваших данных. Предметные фотографии не доказывают точность на игровых мини-картах. Если нужен центр объекта или маска, это отдельный этап уточнения.

## Отмена, нагрузка и ошибки

Переиспользуйте один `client` на жизненный цикл сервиса. По умолчанию одновременно выполняются две операции, в очереди допускается 16, общий тайм-аут — 45 секунд, включая ожидание очереди и обработку картинки. Параметры можно задать в `createClassifier`; максимумы — 4 операции, 32 ожидающих и 120 секунд. При переполнении возвращается `CAPACITY`, вместо неограниченного накопления задач.

Для отмены передайте `signal`. Например, этот вызов завершается не позднее тайм-аута сигнала с учётом физического освобождения нативных ресурсов:

```js
const result = await client.classify({
  input: 'Нужна помощь со входом',
  classes: [
    { id: 'support', description: 'Техническая проблема' },
    { id: 'other', description: 'Другая тема' },
  ],
  signal: AbortSignal.timeout(10_000),
})
```

Для ручной отмены создайте `AbortController`, передайте `controller.signal`, вызовите `controller.abort()` при закрытии запроса пользователя. `await client.dispose()` отменяет активные/ожидающие операции и ждёт фактического завершения принадлежащих клиенту работ. Отмена уже отправленного HTTP-запроса не гарантирует отмену тарификации у провайдера.

Обрабатывайте `ClassifierError` через экспорт библиотеки:

```js
import { ClassifierError } from 'zorya-classifier'

try {
  // await client.classify(...) или await client.locate(...)
} catch (error) {
  if (error instanceof ClassifierError) {
    console.error(error.code, error.message)
  } else {
    throw error
  }
}
```

Коды включают `INVALID_INPUT`, `INVALID_RESPONSE`, `TIMEOUT`, `ABORTED`, `CAPACITY`, `DISPOSED`, `PROVIDER`, `AUTHENTICATION`, `UNSUPPORTED`, `RESOURCE_LIMIT`. Автоматических повторов, замены модели и провайдера нет. Собственный повтор учитывайте как новый платный запрос; `locate` к моменту ошибки уже мог выполнить предыдущие стадии.

## Командная строка

CLI использует переменную `OPENROUTER_API_KEY`. Если она уже настроена в окружении:

```sh
npx --no-install zorya-classifier --help
npx --no-install zorya-classifier classify-text "Где мой заказ?" classes.json
npx --no-install zorya-classifier classify-image photo.jpg classes.json
npx --no-install zorya-classifier locate photo.jpg "красный рюкзак"
```

`classes.json` — обычный массив:

```json
[
  { "id": "delivery", "description": "Вопрос о доставке" },
  { "id": "other", "description": "Другая тема" }
]
```

Для загрузки `.env` без дополнительных зависимостей:

```sh
node --env-file=.env node_modules/zorya-classifier/dist/cli.js locate photo.jpg "красный рюкзак"
```

CLI выводит JSON и обращается к реальному платному провайдеру. `--help` запросов не делает.

## Что показала проверка

В полном записанном прогоне классификация фотографий дала **55/60**, текстов — **30/30**; отдельные вызовы нативного Jev Choice дали те же выбранные классы. Преимущество по точности над Jev не установлено. Тексты — авторские тестовые примеры, не пользовательский трафик.

Локализация остаётся экспериментальной. Полный ранний прогон дал 20 попаданий на 50 положительных фотографиях, 23 ошибки протокола на всех 60 фото и 7 неопределённых ответов. После исправления обработки округлённых вероятностей прошёл отдельный небольшой smoke-прогон без протокольных ошибок; он не заменяет повторную оценку всей выборки. Сохранены и исходные ошибки, и условия проверки.

Классификация фото в полном прогоне занимала p50 2,84 с / p95 4,29 с, текста — 0,28 / 0,32 с. Три стадии поиска — 13,64 / 22,23 с. Это измерения конкретного прогона с подготовкой/записью benchmark-артефактов, а не обещание задержки. Подробные результаты, версии и стоимость: [results](results.md), [приёмка](acceptance.md).
