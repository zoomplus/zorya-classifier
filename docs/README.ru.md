# Zorya Classifier: руководство

Версия 0.2 добавляет прозрачный PNG, бинарную маску, её рамку и центр. Прежний поиск области служит подсказкой для сегментации всего исходного изображения. Затем порт решений проверяет рамку; допускаются одно расширение маски и повторная проверка. [Руководство](v02-usage.md) описывает API, CLI и владение ресурсами.

[Независимый тест 80 случаев](evidence/v02/region-seeded-heldout-v3/README.md) прошёл согласованные критерии, но показал ограниченную полноту: 26/60 попаданий в область объекта и 8/60 полных рамок, без ложных выделений на 20 отрицательных случаях. Из 30 эталонных масок восемь достигли IoU 0,8, три не достигли, для 19 предсказание отсутствовало. Это результаты одной явно настроенной комбинации Luna/OpenAI и MobileSAM, а не гарантия для любой модели или игры.

Сравнение шести способов передачи изображения текстом завершено на свежих фотографиях и реальном интерфейсе: ни один не прошёл требования локализации. [Результаты и ограничения](evidence/v02/fresh-text/README.md) сохранены, публичный экспериментальный режим явно возвращает `UNSUPPORTED`.

Zorya Classifier — библиотека для Node.js и TypeScript с поддерживаемой классификацией по тексту и изображениям и экспериментальной, не квалифицированной для общего применения пространственной локализацией и извлечением объектов. Библиотека не выбирает и не подключает модель за приложение: клиент получает явно переданный `DecisionPort` — готовый адаптер с выбранными настройками или собственную реализацию. Модель и провайдер в примерах — лишь варианты интеграции, не значения по умолчанию. Код распространяется по MIT; веса модели в поставку не входят, запросы удалённых моделей оплачиваются отдельно; можно подключить и свой локальный сервер. Совместимость и качество зависят от выбранного маршрута. Более мощная модель может помочь, но улучшение точности не гарантировано. Проверенные комбинации и результаты перечислены в [таблице моделей](vision-results.md).

Это самостоятельная библиотека: ей не нужны Zorya Games, Electron, база данных или игровой процесс. Её можно встроить в сервер, бота, инструмент обработки фотографий или собственный HTTP-сервис. Готовый постоянно работающий HTTP-сервер в пакет не входит.

## Статус возможностей

Дальнейшие эксперименты по точности пространственных сценариев остановлены; ни одна стратегия локализации, извлечения или предложений масок не продвигается для общего использования. Исторические метрики в `docs/evidence/**` сохранены без переинтерпретации.

| Возможность                                   | Статус           | Примечание                                                                     |
| --------------------------------------------- | ---------------- | ------------------------------------------------------------------------------ |
| `classify` с явным `DecisionPort`             | Поддерживается   | Один закрытый ID класса; без заявления об универсальной точности модели        |
| `locate` (сетка регионов)                     | Экспериментально | Гипотеза по ячейке, не геометрия целого объекта и не доказательство отсутствия |
| `RefinementPort`                              | Экспериментально | Без общей квалификации качества                                                |
| `locate({ mode: 'whole-object' })`            | Экспериментально | Интервалы или сегментация вызывающего; без квалификации                        |
| `extract`, `SegmentationPort`, проверка рамки | Экспериментально | Структурный успех ≠ семантическая точность маски                               |
| `objectProposals`, нативные фабрики           | Экспериментально | На стороне вызывающего; без квалификации                                       |
| `experimental-text`                           | Отклонено        | `UNSUPPORTED`, пока профиль не пройдёт отбор                                   |

Heldout region-seeded (один задокументированный рецепт): 26/60 попаданий seed на позитивах; 8/60 полных рамок объекта; на 30 эталонных масках — 8 с IoU 0,8, 3 неудачи, 19 без предсказания. H8 DEV: 7/9 позитивов и 2/3 ложных выхода, без квалификации. Узкий исторический admission — не общая пространственная квалификация.

## Что умеет

| Задача                                                     | Статус           | API                                 | Результат                                                                         |
| ---------------------------------------------------------- | ---------------- | ----------------------------------- | --------------------------------------------------------------------------------- |
| Распределить обращения по отделам, определить намерение    | Поддерживается   | `classify` с текстом                | Один из заданных классов и ранжирование вариантов                                 |
| Проверить наличие объекта или выбрать категорию фотографии | Поддерживается   | `classify` с изображением           | Один из заданных классов                                                          |
| Оценить изображение с текстовым условием                   | Поддерживается   | `classify` с текстом и изображением | Класс с учётом обоих входов                                                       |
| Найти примерную область предмета, значка или указателя     | Экспериментально | `locate`                            | Ячейка в координатах исходного изображения либо явная неопределённость/отсутствие |
| Получить маску, рамку, центр и прозрачный вырез предмета   | Экспериментально | `extract` с явным сегментатором     | Геометрия и вырез, выведенные из пикселей маски                                   |

Для `extract` после сегментации порт решений получает полный исходник с рамкой из маски и исходной подсказкой `seed`. Ответ закрыт: `complete` (можно вернуть результат и опциональный вырез), `needs-expansion` (не более одного расширения охватывающей маски и одной финальной проверки; повторный `complete` после финальной проверки тоже допускает результат) или `unknown` (неразрешённая проверка, нет поддержки расширения, нет действительной охватывающей маски или провал финальной проверки — второго расширения нет). Внутри одного `extract` со встроенным `locate` — до трёх запросов на поиск области и до двух закрытых проверок рамки. Без подтверждения библиотека возвращает неопределённость и не публикует частичный вырез. Рамка и центр только из пикселей маски; успешная проверка рамки не доказывает идеальную сегментацию по пикселям. Порт решений подключается через `DecisionPort`; сегментатор остаётся на стороне вызывающего.

Сконфигурированный `DecisionPort` выполняет запросы по контракту библиотеки. `classify` делает один запрос, а `locate` — до трёх последовательных запросов: крупная сетка → уточнение в четырёх выбранных областях → сравнение четырёх увеличенных кандидатов. Проверки присутствия входят в те же запросы. Порт отвечает за ответы, координаты вычисляет код.

Библиотека не генерирует описание сцены и не ищет все экземпляры предмета: если подходящих объектов несколько, `locate` возвращает один кандидат. Выбранная ячейка может содержать только часть объекта; это не маска сегментации, не точная рамка и не доказанный центр. Дополнительный алгоритм уточнения можно подключить через `RefinementPort`.

## Установка и ключ

Нужен Node.js 22.12 или новее. Сводка измеренных контрольных точек рефакторинга (Linux Node 22/24, Windows, интерпретатор Python) и статус волн 1–9 — в [плане рефакторинга](refactoring-plan.ru.md); здесь не дублируется. Зависимости среды выполнения — Zod и Sharp, включая платформенный нативный модуль Sharp.

Исходники: [zoomplus/zorya-classifier](https://github.com/zoomplus/zorya-classifier). Пакет: [zorya-classifier в npm](https://www.npmjs.com/package/zorya-classifier). Установка из реестра:

```sh
npm install zorya-classifier
```

Для локального/релизного архива также работает `npm install ./zorya-classifier-0.2.0.tgz` (имя следует версии в `package.json`; это не заявление о новой публикации в npm).

Скопируйте пример конфигурации в локальный `.env` и заполните значение `OPENROUTER_API_KEY` своим ключом. В репозитории `.env` исключён из Git; в своём проекте тоже добавьте это исключение. Не помещайте ключ в браузерный React-код, приложение клиента или публичный репозиторий. Вызовы модели выполняйте на доверенном сервере.

Создайте `example.mjs` и запустите:

```sh
node --env-file=.env example.mjs
```

Эта команда работает и в PowerShell, и в Linux shell. Вместо файла можно передать переменную окружения средствами вашего сервера/менеджера секретов. Библиотека сама `.env` не читает; флаг обрабатывает Node.js. Ключ требуется только реальному адаптеру; обычные тесты работают без него.

## Первый пример: классификация текста

Полный файл `example.mjs`:

```js
import { createClassifier } from 'zorya-classifier'
import { createOpenRouterDecisions } from 'zorya-classifier/openrouter'

const apiKey = process.env.OPENROUTER_API_KEY
if (!apiKey) throw new Error('Заполните OPENROUTER_API_KEY')

const client = createClassifier({
  decision: createOpenRouterDecisions({
    apiKey,
    model: 'openai/gpt-6-luna-decisions',
    provider: 'openai',
  }),
})

try {
  const result = await client.classify({
    input: 'Заказ ещё не приехал. Где посмотреть доставку?',
    classes: [
      { id: 'delivery', description: 'Вопрос о доставке или отслеживании заказа' },
      { id: 'refund', description: 'Просьба вернуть деньги или товар' },
      { id: 'other', description: 'Любое другое обращение, не относящееся к доставке и возврату' },
    ],
  })
  console.log(result.choice)
  console.log(result.probabilities)
  console.log(result.metadata)
} finally {
  await client.dispose()
}
```

Передавайте от 2 до 255 классов с уникальными `id`. Описывайте различия между ними явно. Если ни один предметный класс может не подойти, добавьте `other` или `none` с точным условием выбора: скрытого универсального класса «не знаю» здесь нет.

`choice` — выбранный класс. В основном native-режиме возвращается настоящее распределение `probabilities` провайдера: выбирается максимум, при равенстве — первый заданный класс, без общего порога0.8. Для обычной языковой модели `probabilities` и `nativeChoice` равны `null`: баллы не выдумываются из порядка вариантов. Ответ обязан содержать только допустимые уникальные ID; некорректный JSON, лишние вопросы, отказ и обрезанный ответ считаются ошибкой. Правильная форма JSON ещё не доказывает фактическую правильность классификации.

Для обычных языковых моделей используйте `createOpenRouterVision` с явными `model`/`provider`, например `openai/gpt-6-luna` и `openai`. Он работает через chat completions. Для классификации нужен один ID, для двух пространственных этапов — четыре упорядоченных кандидата. Нативный Jev-адаптер сохранён отдельно для совместимости и исторических сравнений; автоматического перехода на него нет.

## Классификация изображения

Внутри того же `try` можно передать изображение и дополнительный текст. Добавьте `readFile` к импортам:

```js
import { readFile } from 'node:fs/promises'

const result = await client.classify({
  input: {
    image: await readFile('photo.jpg'),
    text: 'Есть ли на фотографии велосипед, включая частично видимый?',
  },
  classes: [
    { id: 'present', description: 'На изображении виден хотя бы один велосипед' },
    { id: 'absent', description: 'На изображении нет видимого велосипеда' },
  ],
})
```

Для одной картинки поле `text` можно опустить. Принимаются `Uint8Array` и `Buffer` с одним PNG/JPEG/WebP: до 16 MiB и 16 777 216 декодированных пикселей. Ссылки на изображения публичный API не загружает — скачивание, права доступа и ограничения внешних URL остаются у вызывающего приложения.

## Поиск объекта и координаты (экспериментально)

Обычный `locate` экспериментален и не квалифицирован для общего применения. Также внутри `try`:

```js
const result = await client.locate({
  image: await readFile('photo.jpg'),
  target: 'красный рюкзак на стуле',
  exclusions: ['сумка на полу'],
})

if (result.status === 'located') {
  console.log(result.region) // left, top, width, height: пиксели
  console.log(result.normalizedRegion) // те же поля в долях размеров изображения
  console.log(result.metadata.image) // размеры и система координат
} else {
  console.log(result.status, result.reason)
}
```

Начало координат — левый верхний угол изображения после применения его EXIF-ориентации. X растёт вправо, Y вниз. `region` включает левую/верхнюю границы и не включает правую/нижнюю. Для экранного оверлея сначала учитывайте ориентацию, масштаб отображения и возможные поля вокруг картинки. Не переносите координаты на следующий кадр без проверки: библиотека не отслеживает объект во времени.

`roi: { left, top, width, height }` ограничивает поиск прямоугольником в целых пикселях того же ориентированного исходника. Координаты ответа остаются относительно всего исходника, а не относительно обрезанного фрагмента. Указывайте ROI только если он находится внутри реальных размеров изображения.

| Статус                       | Что означает                                                                        | Как обрабатывать                                                                            |
| ---------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `located`                    | Выбран кандидат в сетке                                                             | Показать область с учётом вероятностного характера результата                               |
| `not-found`                  | Проверка присутствия отвергла объект в анализируемой области                        | Не переносить этот вывод на область за пределами ROI                                        |
| `unknown`                    | Неуверенность, противоречие, отсутствие цели среди кандидатов или невозможная сетка | Уточнить цель, взять более подходящее изображение или вернуть пользователю неопределённость |
| Исключение `ClassifierError` | Ошибка входа, сети, протокола, бюджета или жизненного цикла                         | Обработать код ошибки; не показывать её как отсутствие объекта                              |

Если нужны маска, рамка или центр объекта, используйте `extract` с явно созданным сегментатором. Обычный `locate` сначала находит регион-кандидат; затем сегментатор получает подсказку `seed` на всём ориентированном исходном изображении. Рамка и центр вычисляются по реальным пикселям маски. После сегментации **текущий** основной поток выполняет до **двух** закрытых проверок рамки на полном исходнике (`complete` / `needs-expansion` / `unknown`) через `DecisionPort`, с не более чем одним расширением маски и финальной проверкой; обрезка, масштаб и поля вокруг изображения сохраняют соответствие исходника и маски, а подготовка вида для проверки идёт через `RasterPort.imageState` на полном холсте. Пример и владение ресурсами — [руководство 0.2](v02-usage.md), [architecture.ru.md](architecture.ru.md). Это технический путь, а не гарантия точности на всех фото.

В типичной композиции приложение сначала вызывает `classify` для наличия цели и запускает `extract` только после ответа `present`. Это **явная** композиция: **1** запрос классификации + до **3** запросов `locate` + до **2** запросов проверки рамки внутри `extract` — **до 6** запросов порта решений суммарно. Сам `extract` отдельную классификацию не подставляет. Ошибку классификации нельзя выдавать за отсутствие цели. Вызывающий **может** передать один `AbortSignal` или общий предельный срок на **несколько** вызовов в своём сценарии, но библиотека держит **один абсолютный предельный срок на каждую отдельную операцию**, включая ожидание в очереди; **два** отдельных вызова **не** делят один предельный срок автоматически.

Встроенный MobileSAM получает точку в центре найденной области и обрабатывает весь исходник; текст названия предмета он не понимает. Поэтому иногда он выделяет деталь, например фару вместо автомобиля. Успешный `extracted` подтверждает корректность маски и файлов, а точность распознавания оценивается отдельно. На полном DEV40 для v2 было 18/30 попаданий области в рамку цели, 5/30 совпадений рамки маски и 0 ложных вырезок на 10 отрицательных примерах. Это разные метрики. [Независимый отчёт](evidence/v02/region-seeded-dev-v2/README.md) сохраняет ошибки и ограничения; другой сегментатор подключается через тот же `SegmentationPort`.

## Отмена, нагрузка и ошибки

Переиспользуйте один `client` на жизненный цикл сервиса. По умолчанию одновременно выполняются две операции, в очереди допускается 16, общий тайм-аут — 45 секунд, включая ожидание очереди и обработку картинки. Параметры можно задать в `createClassifier`; максимумы — 4 операции, 32 ожидающих и 120 секунд. При переполнении возвращается `CAPACITY`, вместо неограниченного накопления задач.

Для отмены передайте `signal`. Операция перестаёт принимать результат после отмены или тайм-аута, но **может** удерживать слот и завершать физическую работу (HTTP, Sharp, принадлежащий нативный дочерний процесс) до фактического завершения — момент возврата из вызова по календарному времени **не** обещает мгновенного освобождения всех нативных ресурсов. Пример:

```js
const result = await client.classify({
  input: 'Нужна помощь со входом',
  classes: [
    { id: 'support', description: 'Техническая проблема' },
    { id: 'other', description: 'Другая тема' },
  ],
  signal: AbortSignal.timeout(10_000),
})
```

Для ручной отмены создайте `AbortController`, передайте `controller.signal`, вызовите `controller.abort()` при закрытии запроса пользователя. `await client.dispose()` отменяет активные/ожидающие операции и ждёт фактического завершения принадлежащих клиенту работ. Отмена уже отправленного HTTP-запроса не гарантирует отмену тарификации у провайдера.

Обрабатывайте `ClassifierError` через экспорт библиотеки:

```js
import { ClassifierError } from 'zorya-classifier'

try {
  // await client.classify(...) или await client.locate(...)
} catch (error) {
  if (error instanceof ClassifierError) {
    console.error(error.code, error.message)
  } else {
    throw error
  }
}
```

Коды включают `INVALID_INPUT`, `INVALID_RESPONSE`, `TIMEOUT`, `ABORTED`, `CAPACITY`, `DISPOSED`, `PROVIDER`, `AUTHENTICATION`, `UNSUPPORTED`, `RESOURCE_LIMIT`. Автоматических повторов, замены модели и провайдера нет. Собственный повтор учитывайте как новый платный запрос; `locate` к моменту ошибки уже мог выполнить предыдущие стадии.

## Командная строка

CLI требует явный `ZORYA_MODEL`; режим CLI по умолчанию — `ZORYA_MODE=decisions`. Это настройка команды, а не выбор модели внутри библиотеки. Для обычной языковой модели или прямого чат-сервера установите `ZORYA_MODE=chat`. Для OpenRouter задайте также `OPENROUTER_API_KEY` и `ZORYA_PROVIDER`. Для прямого API или локального сервера задайте полный `ZORYA_ENDPOINT` и при необходимости отдельный `ZORYA_API_KEY`; ключ OpenRouter туда не передаётся. Необязательные `ZORYA_REASONING_EFFORT` и `ZORYA_RESPONSE_FORMAT` используйте только при поддержке сервером. Например, одна из конфигураций Luna Decisions:

```sh
export ZORYA_MODE=decisions
export ZORYA_MODEL=openai/gpt-6-luna-decisions
export ZORYA_PROVIDER=openai
npx --no-install zorya-classifier --help
npx --no-install zorya-classifier classify-text "Где мой заказ?" classes.json
npx --no-install zorya-classifier classify-image photo.jpg classes.json
npx --no-install zorya-classifier locate photo.jpg "красный рюкзак"
```

`classes.json` — обычный массив:

```json
[
  { "id": "delivery", "description": "Вопрос о доставке" },
  { "id": "other", "description": "Другая тема" }
]
```

Для загрузки `.env` без дополнительных зависимостей:

```sh
node --env-file=.env node_modules/zorya-classifier/dist/cli.js locate photo.jpg "красный рюкзак"
```

CLI выводит JSON и обращается к реальному платному провайдеру. `--help` запросов не делает.

## Провайдеры и проверенные модели

OpenRouter — один из способов подключения. Для прямого провайдера или локального сервера:

```js
import { createOpenAICompatibleVision } from 'zorya-classifier/openai-compatible'

const decision = createOpenAICompatibleVision({
  endpoint: 'http://localhost:8000/v1/chat/completions',
  model: 'your-deployed-vision-model',
})
const client = createClassifier({ decision })
```

Укажите настоящий ID развёрнутой модели и полный URL доверенного сервера. Для облачного API можно передать `apiKey`, а для другого способа авторизации — `headers`. Для API с другим протоколом реализуйте экспортируемый `DecisionPort`. Ключ OpenRouter не подставляется автоматически в запрос к вашему серверу. Локальный пример показывает настройку подключения; он не означает, что конкретная модель или сервер были проверены в реальном прогоне.

Для `classify` с одной картинкой достаточно поддержки одной картинки. Для трёхэтапного `locate` модель/сервер должны принимать несколько изображений в одном запросе, максимум девять. Поддержка JSON Schema и JSON-object опциональна: по умолчанию схема описывается в промпте, а ответ проверяется кодом. Модель без нативной классификации подходит; модель, которая не выполняет контракт ответа, вернёт явную ошибку.

[Таблица проверенных моделей](vision-results.md) содержит названия, провайдеров, число примеров, ошибки, точность, задержки и цену. Там отдельно указаны полноценная проверка на корпусе, короткий screening и тесты адаптера с искусственным сервером. Необозначенная модель не считается автоматически проверенной.

Исторический Jev-прогон дал 55/60 на фото и 30/30 на авторских текстовых примерах. Это исходный эталон прежнего адаптера, а не доказательство качества или превосходства другой модели. Результаты не позволяют предполагать, что более мощная модель обязательно повысит точность. Подробности и исходные ошибки сохранены в [исторических результатах](results.md). Локализация остаётся экспериментальной; ячейка не является точной маской или центром объекта.

## Разработка и следующие документы

```sh
npm ci --ignore-scripts
npm run prepare
npm run check
npm run pack:check
npm run format:check
```

`check` включает секреты, TypeScript, ESLint, границы слоёв, неиспользуемый код, тесты и сборку. Husky проверяет добавленные в Git версии файлов. `pack:check` устанавливает архив в независимый проект-потребитель, проверяет его файлы и API. Эти проверки не вызывают реальную модель.
