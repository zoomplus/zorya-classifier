# Public API

Spatial localization, whole-object location, extraction, `RefinementPort`, caller-owned segmentation/box-check composition, `objectProposals`, and native segmentation factories are **experimental and unqualified** for general use (TypeScript `@experimental` on the corresponding public types and methods). Closed `classify` and explicitly configured `DecisionPort`/transport adapters remain supported; they do not imply universal model accuracy. Further spatial accuracy experiments are stopped; no strategy is promoted.

`createClassifier({ decision, timeoutMs?, concurrency?, maxQueue?, maxInputBytes?, refinement?, segmentation?, objectProposals? })` creates an owned client. Defaults: 45,000ms absolute budget including queue/image work/provider work; two active operations; sixteen waiters; 64 MiB total admitted input bytes, reserved before copying. Configured maxima: 120s, four active,32 queued,256 MiB admitted input. Input images are at most16MiB and16,777,216 decoded pixels, with source sides at most16,384; single PNG/JPEG/WebP only. The vision adapter accepts prepared PNG/JPEG with sides280..1568 and a32MiB total request cap. Byte inputs are copied before the first await, including Buffer views.

The caller supplies the `DecisionPort`; the library never chooses a model, provider or endpoint. You may inject a port directly or explicitly construct one of the adapters below. Their model/provider values are examples or benchmark recipes, not defaults, and stronger models do not guarantee higher accuracy. Optional segmentation adapters are configured separately and require caller-installed runtime packages and caller-supplied local assets.

The [0.2 guide](v02-usage.md) documents `extract`, mask-derived `locate({ mode: 'whole-object', ... })`, optional native adapters and the reserved experimental representation selector. Default region behavior is unchanged. The primary object flow runs the original region locator, then prompts the caller-configured segmenter on the full oriented source image; the actual mask determines bounds, center and cutout. A closed containment check then sees the full source with the actual mask-derived box and seed anchor. An incomplete box can trigger one optional `SegmentationPort.expand(input, previousMask)` and one final check; missing support or unresolved verification returns `unknown/segmentation-uncertain`. The previous mask is full-source binary-u8. `segmentationBoxCheck` can inject a custom checker; otherwise the same caller-supplied `decision` is reused. `verification.checks` retains each closed decision and `verification.expansion` records the correction path; all decision receipts contribute to localization metadata. This checks box containment separately from pixel-mask quality, without an extent search. Native factories are exported from `zorya-classifier/segmentation`; the caller supplies and disposes the segmenter separately. `objectProposals` and interval-based whole-object location remain optional legacy strategies. The segmentation entry also exports `packBinaryMask`/`unpackBinaryMask` for custom adapters.

`classify({ input, classes, instructions?, signal? })`: input is a string or `{ text?, image? }` with at least one field. Classes are2..255 distinct IDs plus descriptions. IDs match `[a-zA-Z][a-zA-Z0-9_-]*`; descriptions at most300 chars. Text is at most32,000 chars, custom instructions4,000. Define explicit none/other behavior in your classes. With ordinary vision models the result contains `choice` (first ranked ID), `ranking`, `probabilities: null`, `nativeChoice: null`, empty `tied`, and metadata. No rank is converted to a fabricated probability. Optional native integrations instead retain raw probabilities, stable maximum/ties, native choice/confidence and optional quantization annotation. Confidence is never a calibrated spatial guarantee.

`locate({ image, target, exclusions?, roi?, signal? })` (**experimental**): target at most2,000 chars; up to16 exclusions of500 chars. ROI uses integer `left/top/width/height` in EXIF-oriented source pixels. Return coordinates reference that oriented image; metadata names this space and dimensions. Rectangles include left/top and exclude right/bottom. Normalized rectangle fields are divided by image dimensions. Tiny/impossible bounded grids return `unknown/layout-limit`.

`located` from default region mode returns a selected grid region, normalized region, third-stage selection evidence and optional refinement. `not-found/absent-in-evaluated-region` is based on the initial independent presence check. A target missing from later shortlisted cells yields `unknown/candidate-union-empty`, not global absence. Ordinary models return present/absent/unknown as an independent categorical predicate. Legacy Noul0.5 abstains; contradictory presence/selection returns unknown. Multiple physical matching objects are permitted; this is an any-instance locator. With an explicit `segmentation` port, `locate({ mode: 'whole-object' })` and `extract` use the region seed plus full-source segmentation; reported bounds and center come from the valid mask.

The algorithm searches4×4 coarse cells, keeps four source-distinct maxima, pads each by half a coarse cell within ROI, partitions each into at most49 fine cells (global≤196, side≤256), then compares the four best fine cells as enlarged A–D/none. Edges count as matches. Scores/rank hints are not sent to the final comparison. No cell-center correction is presented as object segmentation.

`RefinementPort.refine({ image, target, region, signal })` (**experimental**) is optional trusted code. It receives a private oriented-source byte copy. A returned refined rectangle must fit the source and intersect the selected cell. It does not replace the original area evidence. No built-in heavy refiner is downloaded.

`dispose()` cancels current/queued work, rejects further calls and waits for physical settlement. Injected ports must honor cancellation. Native image work retains its concurrency slot until completion, even if cancellation has already been requested.

`ClassifierError.code`: INVALID_INPUT, INVALID_RESPONSE, TIMEOUT, ABORTED, CAPACITY, DISPOSED, PROVIDER, AUTHENTICATION, UNSUPPORTED, RESOURCE_LIMIT. Transport failures throw; they are not successful negative classifications. Provider metadata uses null for unknown model/provider/request/cost. Localization adds knownCostUsd and unknownCostCount; knownCostUsd alone is not a complete bill when unknownCostCount>0.

## Optional native decision adapter

`createOpenRouterDecisions({ apiKey, model, provider, providerName?, responseModelIds?, probabilityRoundingStep?, fetch?, maxRequestBytes?, maxResponseBytes? })` uses the typed `/api/alpha/decisions` endpoint. One documented example route is `openai/gpt-6-luna-decisions` / `openai`. Model and provider are required; `provider.only` disables fallback. Compatible native models can be supplied explicitly; vision support and factual quality must be checked per model. Jev is not required. The adapter is opt-in and is never selected by the library on its own.

The adapter sends the exact Choice criteria and independent Noul questions, preserving genuine raw distributions and metadata. Internal chat-only `rankingSize` hints are stripped from the native wire request. Model/provider identity, question correspondence, complete finite probabilities and the categorical maximum are verified. Valid date-stamped model snapshots are accepted. `probabilityRoundingStep` is unset by default: a selected model does not inherit Jev's observed0.01 wire quantization. Set it explicitly only with supporting provider/wire evidence; values are still never normalized.

Other native protocols can implement `DecisionPort`. No native-to-chat or model/provider fallback occurs automatically.

## Ordinary vision chat adapters

`createOpenAICompatibleVision({ endpoint, model, apiKey?, headers?, responseFormat?, maxOutputTokens?, reasoningEffort?, responseModelIds?, fetch?, maxRequestBytes?, maxResponseBytes? })` is exported from `zorya-classifier/openai-compatible`. The full HTTP(S) chat-completions URL is explicit and trusted; URL user/password credentials are rejected. Anonymous local servers can omit authentication. Custom headers support other server authentication. Supply either `apiKey` or a custom Authorization header, not both. No OpenRouter routing fields are sent by this adapter.

`createOpenRouterVision({ apiKey, model, provider, providerName?, ... })` is exported from `zorya-classifier/openrouter`. It wraps the same ordinary chat transport with a fixed OpenRouter chat-completions endpoint and explicit `provider.only`, no fallback, and required parameter support. `providerName` identifies a returned display name differing from the requested slug. Additional explicitly allowed response model snapshot IDs can be listed in `responseModelIds`; these are identity aliases, not alternative routes. Date-stamped snapshots of the requested model are accepted and preserved in metadata.

`responseFormat` is `prompt` by default, requiring only ordinary instruction-following JSON output, not provider-native structured outputs. `json-object` and `json-schema` are explicit opt-ins when the model/server supports them. `maxOutputTokens` defaults to1024, maximum4096. `reasoningEffort` is optional; do not request unsupported parameters from a custom model. No temperature or reasoning option is silently imposed by the generic adapter.

The model is given the exact class descriptions and required JSON shape. It returns one ranked ID for classification/final candidate selection and exactly `min(4, option count)` unique ranked IDs for each spatial beam question (`rankingSize: 1 | 4`; omitted defaults to4 on direct port calls) and an explicit present/absent/unknown for each presence question. The adapter checks all questions, IDs, types, finish state and byte limits. It rejects unknown IDs, duplicate/incomplete ranks, numeric probabilities invented in a ranking response, extra answers, malformed/fenced JSON, refusals, tool output and truncated generations. There are no hidden corrective retries. Factual correctness still depends on the model.

The public `DecisionPort` supports another SDK/protocol. For a ranked answer, return `{ type: 'ranked-choice', ranking: [...] }`; for presence return `{ type: 'presence', presence: 'present' | 'absent' | 'unknown' }`, with truthful route/cost metadata. The caller's deadline-bound AbortSignal must be honored. Optional legacy probability answers remain supported. `classify` needs at most one image; `locate` requires up to nine images per request. A server supporting only a single image is not claimed to support the locator.

`createOpenRouterJev({ apiKey, fetch?, maxRequestBytes?, maxResponseBytes? })` is an optional legacy Jev integration, never the required backend or an automatic fallback: fixed endpoint/model/provider, no automatic fallback/retry. Lower request/response caps can be supplied; response defaults1MiB. Direct port calls require the caller to supply a deadline-bound signal. The top-level client supplies it. The port accepts only top-level inline image parts, not remote URLs.

## Optional legacy native adapter and quantization

The legacy Jev adapter observed Jev 1.14 rounding scores to a 0.01 lattice: a real 153-option response sums to 0.99. Such values remain raw; they are never renormalized. For non-unit mass the adapter accepts only finite [0,1] values on that lattice whose clipped half-step intervals jointly admit total probability 1, and adds `probabilityRoundingStep: 0.01`. Complete option keys and the native maximum remain mandatory.

A custom probability-valued `DecisionPort` answer without this explicit annotation must provide unit mass within floating-point tolerance. The annotation describes transport quantization, not calibration or confidence; many tied zeros can be compatible with rounding at high class counts and convey no ranking information. Stable input-order tie selection still applies. The result preserves both the native choice and our deterministic choice.
