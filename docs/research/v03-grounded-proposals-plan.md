# v0.3 text-conditioned proposal probe

Status: bounded DEV candidate-availability probe. No accuracy or quality improvement is claimed before separate evaluation. Reviewed 2026-10-21.

## Decision and limits

If the current H1/H2 work leaves candidate availability as a remaining failure mode, GroundingDINO-T boxes followed by SAM2 Hiera-Tiny box-prompt masks are a practical local complement. Root reports H2 point-oracle mean 0.921 versus native 0.635; this makes more geometric candidates worth testing for photos, UI and maps, not an automatic replacement or a method to rank before measurement. GroundingDINO conditions boxes on text, and SAM2 converts supplied boxes to masks. This is an engineering composition, not an official joint model. The literature and docs support the test hypothesis but do not guarantee corpus improvement.

The existing [`ObjectProposalPort`](../../src/entities/object-proposals.ts) receives image, seed region and ROI but has no text target. Do not change that public contract for this probe. Use a research-only script with a caller-supplied local image root, explicit asset directories and output directory. It creates no model/provider port and makes no semantic choice. It cannot emit a final box, `none`, or a whole-image presence judgment.

## Fixed DEV probe

Use only the twelve producer inputs from existing commit `effc2e8`, four per stratum, with no redrawing or query rewriting: `pilot-v03-photo-01`–`04`, `pilot-v03-ui-01`–`04`, and `pilot-v03-map-01`–`04`. Read only `pilot-inputs/*.json` plus exact source bytes under the explicitly supplied image root. Verify the fixed manifest hashes, case IDs, source SHA256 and dimensions before inference. Never read evaluator truth or evaluator code in the producer. Retain the authored target verbatim beside the normalized detector target.

Use this deterministic, target-only parser for the short noun phrase: preserve single noun labels as authored; otherwise trim a leading article; for UI targets, preserve text before the first `in the` clause (e.g. `Forward navigation button`); for the fixed map syntax `visible body sprite of unit type X in ...`, emit `X unit` (e.g. `Explorer unit`). Add only the fixed article `a ` at the detector API boundary. Reject unmatched syntax. No normalization may depend on image pixels, truth, or model output.

Run GroundingDINO-T once per full source at fixed `box_threshold=0.15`, `text_threshold=0.15`. Preserve all filtered detector outputs in native return order, with raw boxes, labels, scores and count. Pass at most the first 36 detector-return boxes (no score sorting) to SAM2 Hiera-Tiny with `multimask_output=False`; preserve each mask and its source-canvas box. Record any remainder/truncation. Keep native detector and SAM2 mask scores as diagnostics only. A negative may naturally generate irrelevant boxes/masks; candidate count is not a false positive. Only a later closed semantic selector’s final chosen geometry may count as a false location.

The script writes one output row per case and source-canvas candidate mask files into an explicit output directory. Rows include case ID, input/source hash and dimensions, raw/normalized target, model revisions and every asset hash, all detector results, bounded masks and derived boxes, raw quality scores, timings, peak allocated/reserved VRAM and status/failure. Do not put source image bytes, boxes/masks from truth, labels, or evaluator metrics into producer requests or run rows. The script makes no Luna/model/provider selection calls. The evaluator runs only after all producer children have closed and consumes the saved outputs separately.

Run at most one GPU worker. Each case is an owned child process with a 240-second absolute deadline including model initialization; on timeout the parent kills only that child’s process group, records the timeout, and preserves all remaining denominator rows. Stop on source/hash mismatch, implicit model/network fetch during inference, OOM, output-ownership failure or coordinate invariant violation. A negative candidate count is not a stop condition: proposals on a negative are diagnostic availability, and only a closed semantic selector’s final chosen geometry can be a false positive. This producer reports availability only; downstream evaluation decides whether the hypotheses merit continuation.

## Corrective plan after first failed probe

The first fixed 12-case producer run is retained at `/root/work/zorya-classifier/.run/v03/grounded-proposals-h3-run-01` as a closed technical failure: every row has `status: error`; it produced no candidate masks and must not be merged into candidate or semantic evaluation. A one-case diagnostic captured the full traceback: `torch.cuda.reset_peak_memory_stats(cuda:0)` raised `RuntimeError: Invalid device argument` before either model was loaded. In a fresh process, `torch.cuda.is_available()` followed by that reset reproduces the exception; explicit `torch.cuda.init()`, `torch.cuda.set_device(cuda:0)`, and `torch.cuda.synchronize(cuda:0)` before the reset pass. The corrective implementation will perform those calls before CUDA peak counters and add a focused ordering regression. If a new fixed case fails, stop after its first worker error and write explicit `not_run_after_first_error` rows for the remaining fixed denominator rather than repeat a likely global runtime failure twelve times. A corrected run gets a separate directory and separate run hash.

Before the corrected run, freeze the complete isolated `pip freeze --all` output under `/root/work/zorya-classifier-models/v03/python-freeze.txt`. Add `source_freeze.producer_script_sha256` and `source_freeze.environment_freeze_sha256` to `run.json`; retain the existing manifest hashes, per-case `row_sha256`, and pinned model file/revision hashes. The evaluator will receive the closed run path plus an externally supplied SHA256 of its final `run.json`. No truth or evaluator code enters this producer.
