# v0.3 text-conditioned proposal preflight

Status: research plan only. No model was installed or downloaded and no weights were accessed. These sources justify a small experiment, not an expected improvement claim. Reviewed 2026-10-21.

## Recommendation

If H1/H2 leave candidate availability as the main failure, test the official GroundingDINO-T (Swin-T) detector followed by SAM2 Hiera-Tiny box-prompt masks as a caller-owned local adapter. GroundingDINO conditions object boxes on a text prompt and its smallest official checkpoint is the Swin-T variant; SAM2 accepts box prompts and can turn those boxes into masks. This is the most practical first test among the compared options: its two model checkpoints are public, its code and weights use Apache-2.0 terms, and it avoids another fixed point or grid scan. The combination is an inference from the models' documented interfaces; it is not an official joint model and has no measured fit or quality result on this corpus. See the official [GroundingDINO repository](https://github.com/IDEA-Research/GroundingDINO), [SAM2 repository](https://github.com/facebookresearch/sam2), and [SAM2 tiny checkpoint](https://huggingface.co/facebook/sam2-hiera-tiny-hf).

Keep this as a research-only `TextProposalPort` in a separate runner/sidecar initially. The current [`ObjectProposalPort`](../../src/entities/object-proposals.ts) receives image, seed region and ROI but no semantic target; changing that established contract to force text detection into it would be premature. A future caller-owned port needs an explicit `{ image, target, roi, signal }` input, an explicit model/config/checkpoint location supplied at construction, and bounded candidate-mask output in source coordinates. It must not select or download model assets, expose scores to semantic selection, or add a default backend. A native SAM2 prompt box is generated by GroundingDINO, never by the model as free coordinates from a language response.

For this first experiment, use the official GroundingDINO repository at a recorded commit plus the official SAM2 repository and public Hiera-Tiny checkpoint. Pin each repo revision and file checksum in the run manifest before execution. Explicitly stage all files locally, including the GroundingDINO config and its BERT tokenizer/text encoder, and disable implicit model-hub fetches in the runner. The official GroundingDINO setup includes a custom CUDA extension and transformer text backbone; SAM2 can run without its optional CUDA postprocessing extension. The present machine has Python 3.12.3 but no installed `torch`, `torchvision`, `transformers`, Pillow or OpenCV, and no detected model checkpoints in the repository or the two checked standard Torch/Hugging Face cache directories. No package installation, network asset request or checkpoint access was made. The CUDA driver reports RTX 4080, 13,371 MiB free; the CUDA toolkit / `nvcc`, PyTorch CUDA build, and actual inference memory have not been checked.

The GroundingDINO and SAM2 implementations are separate upstream projects; the DINO-T + SAM2 recommendation is an engineering composition, not an official integration. The open-vocabulary claim does not mean that arbitrary game-piece names, map symbols, inventory glyphs or proprietary UI labels are understood. The training distribution and natural-image priors may be poorly matched to tiny flat icons. SAM2 is a mask refiner prompted by a box; it cannot recover an instance that GroundingDINO did not propose. Keep photo, UI-icon and map-icon results separate.

## Exact tiny experiment (run only after H1/H2 and owner selection)

Use one predeclared, frozen 12-case DEV diagnostic: four photographs, four UI/icon cases and four map/icon cases; within each stratum select three positive cases and one verified negative when available. Choose cases from the current DEV corpus and freeze IDs, input hashes, targets, truth references and recipe before dispatch; if a stratum lacks a verified negative, preserve its available denominator and state the resulting limitation. Do not inspect heldout data or outcomes to choose examples, prompts or operating points. Include the full oriented source at its original resolution—no nine-point enumeration, cell tiling, semantic pixel heuristics or crops in this first test.

For each case, run the same explicit target phrase through GroundingDINO-T once on the full source. Set `box_threshold=0.15` and `text_threshold=0.15` for the diagnostic and freeze these values before viewing results. Keep up to the existing 36-candidate contract limit in detector-return order; record every truncation and raw score as diagnostic metadata only. These thresholds control proposal generation, not the final semantic decision. Feed each kept box to SAM2 Hiera-Tiny using the same image embedding and box prompt; retain the selected mask in full source coordinates, packed under stable aliases `C00`–`C35`. The model/provider that might compare candidate masks remains a separate explicitly injected caller choice, with `none`; do not use DINO/SAM quality scores to choose the semantic winner. No hidden OCR, model-generated points, `.8` categorical gate or default provider.

Compare against the current frozen proposal baseline on those same 12 inputs and target phrases. The offline evaluator alone compares output candidates with reference targets. Report, by stratum and paired case: (1) proposal availability: whether any detector box reaches target IoU ≥0.5, (2) mask-derived box coverage/IoU and mask IoU where reference masks exist, (3) positives with zero candidates, negatives with any candidate overlapping an object, candidate counts and truncation, (4) proposal and full-pipeline wall time, peak VRAM, failures and physical model/provider requests. Preserve the full denominator. Treat detector scores as operating-point diagnostics, not calibrated confidence. A positive recall gain accompanied by materially more negative candidates or mask-fragment boxes is not a win.

Fail fast before processing all twelve if any source-coordinate or ROI invariant breaks, any case causes OOM, setup attempts an undeclared network fetch, or a verified negative produces an unsupported candidate under the frozen operating point. Continue through the slice only with full receipts, no resource or ownership violations, and at least one valid positive candidate recovered; then report every case, including unknowns and failures. This pilot is a stop/go diagnostic, not heldout qualification. If positive candidate availability does not improve against the current proposal baseline, pivot away from this model composition rather than adding threshold or tiling variants on the same small sample.

The future prototype plan, before any implementation, is limited to an isolated caller-owned Python sidecar/adapter and a new benchmark runner plus focused tests. It will define bounded image/target input and a maximum of 36 source-coordinate packed masks, request-local abort/settle/dispose semantics, explicit local config/checkpoint paths and hashes, finite diagnostic metadata, and no model fallback or automatic asset retrieval. It will not alter `src/`, `ObjectProposalPort`, package dependencies, lockfiles, default behavior or public contracts until this experiment earns a separate owner-approved integration plan. No improvement is claimed before measurement.
