# H6: context-preserving semantic mask selection

State: accepted research implementation plan, recorded after H5b closed and before H6 implementation or provider dispatch. This is a separately named benchmark experiment, not a change to the public library or a qualified release.

## Failure and hypothesis

The independently closed H5b pilot retained useful masks in 8/9 positive cases, nominated one in 6/9, and selected one in only 3/9. Photos were 3 → 3 → 2, UI 3 → 2 → 1, and maps 2 → 1 → 0. All three negative cases produced false outputs. Its 32 physical requests cost USD 0.0149639, with no unknown charges or transport errors. Preserve [the report](../evidence/v03/h5b-paid-replay-independent-evaluation.json) and [audit](v03-h5b-paid-replay-independent-audit.md). Better native availability alone is not the current bottleneck.

H6 tests a different evidence interface and question sequence. The authored target appears once per request, with short alias criteria instead of repeating target/extent requirements for every option. An explicit source-level presence question precedes mask choices. Nomination emphasizes semantic identity and relations; larger views preserve the neighboring scene. The final choice compares actual masks after semantic shortlisting. This is a combined mechanism experiment; any gain cannot be attributed to just one of these changes without a later ablation.

[Set-of-Mark](https://arxiv.org/abs/2310.11441) motivates visual references linked to actual regions. [Global-Local Context RIS](https://arxiv.org/abs/2303.17811) and [TAS](https://aclanthology.org/2023.findings-emnlp.73/) motivate retaining local and global context when matching an expression to candidate masks. [GUI-Lens](https://arxiv.org/abs/2608.03270) motivates enlarged contextual views for dense interfaces; it studies GUI grounding, not our mask-selection task. [POPE](https://arxiv.org/abs/2305.10355) motivates explicit negative evaluation and cautions that instructions can influence object hallucination. None of these sources proves H6 will improve Luna, and the presence stage is not assumed reliable in advance.

## Fixed inputs and outputs

Use exactly H5a v2's hash-locked native outputs, all 12 pilot rows in their original order, both candidate families D/U in stable producer order, original authored targets, and the unchanged evaluator. No new masks, assets, source edits, per-case crop parameters, OCR, captions, labels, source IDs, or evaluator-derived hints enter requests. Source/mask ownership, source-coordinate geometry, binary foreground validation, 36 candidates per family, 72 total, and 19 MiB packed-mask cap remain unchanged.

The final output is one actual candidate mask or an explicit unknown/error. Coordinates, bounds and transparent extraction continue to derive only from actual source-sized foreground. A model does not generate, enlarge, merge, or repair masks in this experiment.

## Closed decision sequence

1. **presence**: one unmodified full-source image and the authored target. Choice is `present | absent | uncertain`, selected by the native maximum with stable supplied-order ties, not a confidence threshold. Ask only whether the described visible instance exists, not whether any mask is complete. `absent` returns unknown reason `target-absent`; `uncertain` returns unknown reason `presence-unresolved`. Only `present` continues. Record raw selection and metadata in every row; uncertainty is not proof of absence.
2. **nominate-D**: skip an empty family. Full source plus contextual atlas pages for at most 36 D masks; rank four supplied aliases plus `none`. Target text appears exactly once at the end of state. Short criteria identify highlighted regions only. Rank semantic identity and the authored relation; do not require pixel-perfect contour completeness at this stage. A top-four `none` consumes its slot, as in H5.
3. **nominate-U**: identical rules for U. Do not compare numeric scores across the two independent questions.
4. **final-select**: full source plus one context card for each of at most eight nominees. Choose the best actual mask for the described visible instance, preferring coverage of the whole visible instance and excluding substantial unrelated content. Permit occlusion gaps and disconnected visible components. Criteria remain short aliases and `none`; the authored target appears once at the end of state. `none` returns unknown. No extra hidden verifier or retry.

The early presence decision is deliberately evaluated as its own loss stage. Measure positive masks lost by presence, nomination and final selection separately. Evaluate negative presence decisions as well as final false outputs; do not report fewer false outputs without the associated positive losses.

## Deterministic presentation

Use only original pixels and actual mask-derived bounds. For each candidate compute a context rectangle centered on its bounds, with requested width `max(4 * bbox.width, 128)` and height `max(4 * bbox.height, 128)`, clipped to the source with deterministic edge handling. Preserve aspect ratio and identical source/mask transforms; never treat letterbox padding as stretched source content.

Nomination uses at most four atlas pages per family. Each page is a 3 × 3 grid of 480 × 480 tiles (1440 × 1440 pixels). Tile layout: alias in an outside top margin; primary context/actual-mask overlay in a 448 × 344 panel at (16, 40); source-location overview and isolated actual cutout in two 208 × 80 footer panels at (16, 392) and (256, 392). The source-location overview marks the actual mask-derived box for orientation only. Markings must not replace the candidate foreground or imply a new mask. Use the same layout for every candidate, blank unused slots, and stable row-major order. At most five image parts per nomination, including the original source.

Final cards retain a bounded 900 × 320 canvas with outside labels and three panels: full-source location overview, enlarged context with the actual mask, and actual isolated cutout. They use the same deterministic context rectangle. At most nine image parts including the original source. All images pass through the existing caller-injected imageState preparation; no transport-side side-limit relaxation. Keep the existing 20 MiB presentation cap and 240-second absolute per-case replay deadline. If the required fixed view exceeds a limit, retain a typed failure rather than truncating candidates or changing scales silently.
