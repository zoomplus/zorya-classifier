# V0.3 grounded-mask selected-output evaluation

This evaluator scores the closed H3b fixed DEV12 run as a production-path result. It is separate from the H3 candidate-availability ceiling: it joins only the producer's chosen candidate, final box-check decision, saved mask and saved cutout to evaluator-only references.

The external run and freeze SHA-256 values are mandatory inputs. The evaluator also checks the frozen H3 native run identity, both producer-closure digests, the native artifact list, source image hashes and dimensions, and that each persisted case JSON exactly matches its entry in `run.json`. For each selected candidate it verifies the H3 case-row hash, the native mask hash and the native mask file, then requires the emitted full-source binary mask pixels to equal that selected native candidate. This prevents a matching box descriptor from standing in for the output pixels.

Only a row with final status `complete`, box-check verdict `complete`, a non-`none` selected alias, and both mask and cutout files present with matching recorded SHA-256 values can be scored as a completed output. The mask must be a nonempty, binary, source-sized PNG; its foreground bounds are recomputed from the pixels and checked against the recorded bounds. The cutout must be a nonempty RGBA PNG. Rows ending in `needs-expansion`, `unknown`, errors, no candidate, or `none` remain missing outputs even if a diagnostic mask was written. Every one of the nine positive cases remains in the positive denominator; the three negative cases are counted separately, and a completed box on a negative is a false positive.

The localization gate remains unchanged: the same predicted mask-derived box and reference instance must have IoU at least 0.50 and reference coverage at least 0.90. Where a pinned independent reference mask exists, pixel-mask IoU is also reported using the reference's pinned nearest-neighbor resampling policy. Failures to load a reference mask remain explicit and do not remove the case from localization denominators.

The report includes all twelve rows, stratum counts, candidate counts, selection and final statuses, artifact hashes, artifact errors, pixel-derived boxes, IoU and coverage, per-case elapsed times, physical-call accounting, known cost, unknown-cost and in-flight counts, and provider-recorder persistence failures. The runner's complete status and zero unresolved call accounting are required before scoring; incomplete runs are retained as failure evidence and are not qualified results.

The evaluator also recognizes a separately named H3c final-verifier profile. It derives that identity from the paired run/freeze schemas and explicit H3c marker; mixed or relabeled identities fail. H3c additionally requires the frozen producer closure to retain the exact H3b `grounded-mask-selector.ts` SHA-256 (`46416dd3…`) and include the frozen H3c verifier source. The run's initial and final source closures must equal the freeze closure. Its route, no-fallback setting, 120-second case deadline, 24-call cap, and $2 cap are checked independently; the legacy H3b lock path remains unchanged.

For either profile, the evaluator verifies that the final mask matches its selected frozen native mask pixel for pixel and that its recorded box matches the actual mask bounds. It also decodes the cutout and compares its exact RGBA pixels with the source crop restricted by that same binary mask. For H3c, only `match-complete-pure` can qualify a completed output; `wrong-object-or-contaminated`, `match-incomplete`, and `unknown` remain non-locations. H3c quality evaluation is pending until its closed run and exact run/freeze hashes are available.
