# H8a native-selector: DEV8–DEV40 и исправление записи отказа

**Статус:** экспериментальный benchmark-профиль `h8a-cpu-native-selector-flat-v5` остановлен на неполном DEV40. Это не полная оценка качества, не допуск к QUAL и не продвижение профиля в библиотеку или MCP.

## DEV8 и DEV12

На этих отдельных development-экранах V5 показал соответственно 4/5 и 7/9 успешных положительных пар против 1/5 и 1/9 у замороженного v0.2 replay-контроля. На трёх отрицательных парах каждого экрана ложных выходов не было. Восемь пар DEV12 были переиспользованы из DEV8 без изменения; это последовательные малые экраны, а не независимое подтверждение популяционной точности.

В панелях DEV8/12 сохраняются видимые ограничения: обе стороны пропустили кнопку Find; V5 на Extract захватил соседнюю кнопку; на новом положительном случае поля поиска V5 указал на увеличительное стекло, а контроль — на большую часть окна. Подробные результаты и отдельные панели приведены в [русской сводке DEV12](/root/.codex/artifacts/zorya-classifier-mcp-20261101/query-scope-research-v1/native-selector-research-v1/wave35-main-preparation/dev12/results.ru.md).

## DEV40: терминальный STOP

Канонический DEV40 остановлен после 15 завершённых из 40 пар: 11 положительных и 4 отрицательных. В наблюдавшихся положительных парах V5 успешен в 9/11, контроль — в 2/11; обе стороны дали 0 ложных выходов на 4/4 отрицательных парах. Плановый набор содержит 30 положительных и 10 отрицательных случаев: наблюдаемые 9/11 и 2/11 нельзя выдавать за итоговую точность или за полную DEV-оценку.

Из оставшихся 25 неполных пар 24 не запускались ни по одному arm; одна пара Camera частичная: control завершился ошибкой, V5 не запускался. В целом не запускались 49 arm-строк. Этот счёт проверен по всем 40 выходам; исправленная формулировка находится в [v2 результатов DEV40](/root/.codex/artifacts/zorya-classifier-mcp-20261101/query-scope-research-v1/native-selector-research-v1/wave35-main-preparation/dev40/results-v2.ru.md) и [erratum](/root/.codex/artifacts/zorya-classifier-mcp-20261101/query-scope-research-v1/native-selector-research-v1/wave35-main-preparation/dev40/count-wording-erratum-v1.ru.md).

В паре Camera два предыдущих запроса завершились HTTP 200; третий получил HTTP 502 с привязанным к запросу именованным отказом отвечать на вопрос `selection`. У ответа нет response ID и известной стоимости. В отчётной записи typed code `PROVIDER` был сохранён как `PROVIDER_ERROR`, поэтому замороженная политика точного отказа не смогла классифицировать этот исход как `unknown`. Исходный live-прогон остаётся ошибочным и не переклассифицирован задним числом. Это не доказывает общего сбоя провайдера и не устанавливает причину самого HTTP 502.

## W36: исправление только для будущей записи

В изолированном worktree на базе `2572b8c405fc5cd8971a7b39f2683a6f75b65370` подготовлена benchmark-only правка `recordProvider`: помимо локального `instanceof ClassifierError`, рекордер принимает только собственные data-свойства `name: ClassifierError` и `code` из закрытого набора кодов. Это сохраняет типизированные ошибки от другой копии класса без принятия произвольных свойств, getter-значений, generic `Error` или не-Error throws. Маршрутное, request/hash-bound распознавание именованного отказа и его политика не менялись. Публичные библиотечные defaults, API и версии не менялись.

До исправления регрессионный тест воспроизводил потерю `PROVIDER` в `PROVIDER_ERROR` для `ClassifierError` из другой копии класса при точном именованном HTTP 502. После правки целевые тесты прошли **8/8**, typecheck, ESLint, Prettier и `git diff --check` прошли. Главный оркестратор независимо проверил реальный исторический native adapter в трёх сценариях с контролируемым `fetch`:

- точный именованный HTTP 502: `PROVIDER` сохранён, отказ на вопрос selection привязан к исходному запросу, существующая политика отказа сработала;
- обычный HTTP 502: `PROVIDER` сохранён как технический исход, именованный отказ не распознан и политика отказа не сработала;
- типизированный отказ при HTTP 200: `INVALID_RESPONSE` сохранён, поведение существующей политики отказа подтверждено.

Это офлайн-проверка рекордера и адаптера, а не новая модельная оценка: 3 контролируемых вызова `fetch`, 0 настоящих сетевых HTTP-запросов, 0 native inference, без ключей и данных корпуса. Исходный DEV40 не менялся и повторно не запускался. [Аудит главного оркестратора на историческом адаптере](/root/.codex/artifacts/zorya-classifier-mcp-20261101/query-scope-research-v1/native-selector-research-v1/wave36-error-identity-repair/main-historic-adapter-audit-v1.json) и [манифест подготовленной правки](/root/.codex/artifacts/zorya-classifier-mcp-20261101/query-scope-research-v1/native-selector-research-v1/wave36-error-identity-repair/source-manifest-v1.json).

Целевые офлайн-проверки сами по себе не устанавливают полную релизную или платформенную приёмку. Результаты `npm run check`, проверки установленного архива через `npm run pack:check`, CI и интеграции следует фиксировать отдельно. Новый платный DEV не запускался. Поэтому W36 — проверенная целевая исправительная правка, а не завершённая приёмка. Любой будущий прогон DEV должен иметь отдельную идентичность; нельзя использовать исправление для переписывания старых receipts, результатов или расходов.

## Вызовы, стоимость и границы

Кампания V5 до остановки содержит 96 подтверждённых физических вызовов: 41 для candidate и 55 для control; известная стоимость **$0.0355967**, новые неизвестные списания зарезервированы на **$0.12**. Глобальный журнал после остановки: 413 физических вызовов, 134 попытки по arm, **$0.227441215** известной стоимости и **$0.36** резерва неизвестных расходов, из которого $0.24 унаследовано и $0.12 добавлено DEV40. Нет незавершённых или неопределённых вызовов; runtime закрыт, временные файлы удалены.

Кандидат V5 и контроль использовали явно настроенный маршрут Luna Decisions; контроль — замороженное воспроизведение рецепта v0.2, а не прямое сравнение с JevBox. Эти результаты не дают оснований для общего заявления о точности, преимуществе над Jev, скорости или переносимости на другие источники. Порог QUAL не менялся и не достигнут: сначала требуется полный DEV на раскрытой разработочной выборке, затем отдельная независимая QUAL120 с предусмотренными планом уровнями положительных успехов и парного выигрыша, ограничением ложных выходов и критерием mask-IoU. QUAL не приобретался и не запускался; MCP не реализован; публикация библиотеки и продвижение профиля не выполнялись. Независимый аудит полного плана и решение `APPROVE` остаются отдельными условиями завершения.
