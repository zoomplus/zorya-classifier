# Бенчмарк: соблюдение авторской области запроса

**Состояние:** отдельный benchmark-only профиль реализован для будущего DEV/QUAL сравнения. Исследование не зарегистрировано и не проводилось; результатов качества нет. Профиль не продвигается в библиотеку или MCP и не меняет публичные значения по умолчанию.

## Основание и связь с зафиксированной гипотезой

Эта реализация следует зафиксированной гипотезе [о строгом соблюдении авторской области](./v03-authored-scope-hypothesis.ru.md). Предыдущий неполный [provider-refusal replay](./v03-provider-refusal-replay-results.ru.md) завершился на ложном выходе кандидата и не доказывал эффект новой инструкции. Гипотеза, исходные формулировки, старые replay-результаты и их receipts сохранены без изменений. Исторический контекст H8a приведён в [зафиксированном направлении разработки](./v03-h8a-development-baseline.ru.md); он не является результатом этого профиля.

## Контракт оценки

В DEV и QUAL для обоих плеч — authored-scope кандидата и v0.2 контроля — успешная положительная строка с рамкой засчитывается только тогда, когда рамка точно выведена из реальных валидных пикселей приложенной packed mask и проходит прежнее пересечение с эталонной рамкой. Отсутствующий mask ID или bytes, неверная упаковка/геометрия, пустые пиксели и несовпадение объявленной рамки дают нулевой положительный успех. Для отрицательных строк контракт ложного выхода по рамке/cutout не менялся. В legacy raw/flat фазах предсказанная packed mask также требует вывода рамки из маски; сохранён прежний прямоугольный путь только для строки без предсказанной маски, если эталон также не требует exact reference mask.

Численные пороги не менялись. DEV40 не имеет минимального числа положительных успехов; его существующая проверка ложных выходов и полноты остаётся прежней, а отдельное вложенное ревью 8/12 по-прежнему решает, можно ли двигаться дальше. QUAL120 сохраняет минимум 54/90 положительных успехов, 12/30 в каждой страте, парное преимущество не менее 20 п.п., нижнюю границу кластерного парного 95%-го интервала выше нуля, максимум 1/30 ложных выходов и минимум 15/30 независимых фото-масок с IoU ≥0.80. Mask-derived box — требование к валидности положительного результата, а не новый порог качества.

## Текущее состояние и ограничения

Общие entrypoints теперь используют закрытый registry для обоих study ID и один lifecycle: `register`, `run dev8`, `review dev8`, `run dev12`, `review dev12`, `run dev40`, `review dev40`, `closeout`. Каждый вызов требует явные `--protocol` и его SHA-256; production authored-scope admission закрепляет protocol за каноническим путём. Только `run` принимает `--allow-paid`. Следующая стадия требует хеш-связанного отчёта и явного `advance` от main review. Отчёты, review, terminal stop и ledger привязаны к study и protocol. Срок фиксирован; после него новые регистрации и запуски отклоняются, а read-only review/closeout остаются доступны.

Для authored-scope CLI выбирает профиль `h8a-cpu-flat-scope-v3`, flat native recipe `h8a-cpu-flat-target-v2` и query policy `strict-authored-scope-v1`. Legacy CLI сохраняет прежнюю привязку flat-профиля, рецепта и `legacy-v1`. Offline-тесты проходят общий сценарий и отказы границ. В одном тесте подложены 80 искусственных arm-артефактов и три synthetic advance-review; runner закономерно возвращает `qualEligible: true`, потому что существующий DEV gate не задаёт минимум положительных успехов. Это проверка ветки жизненного цикла и sample-файлов, не реальное no-collapse review, не измерение точности и не подтверждение, что такой исход прошёл бы в настоящем запуске. Отдельный partial-closeout тест сохраняет 80 отсутствующих строк и `qualEligible: false`. Финальные проверки и SHA доступны в `runner-wave/cli-checkpoint-v2.md` вне репозитория; `v1` сохранён как pre-fix receipt.

До production запуска нужны закреплённый протокол, чистый закоммиченный checkout и source closure с актуальными SHA-256. Каждый файл closure должен быть прочитан и проверен по хешу через один и тот же открытый дескриптор этого файла; технический main acceptance проверяет эти условия вместе с действующими бюджетами. Ранее предоставленная владельцем авторизация остаётся в силе и не расширяется этой документацией. Фактическая регистрация в `/root/.codex/artifacts/zorya-classifier-mcp-20261101/authored-scope-dev40-v1` не выполнялась; эта production-папка не создавалась, provider-вызовы не проводились.

Проверки lifecycle, схем, замороженных бюджетов и тестовый runtime binding подтверждают только offline-контракт. Они не подтверждают точность профиля. Linux fake-worker runtime test group прошёл **36/36** как техническая offline-проверка: scope binding прошёл runtime ports, H6-композитор и публичный OpenRouter vision adapter через четыре producer stage; native child был подменён `.mjs` worker, provider fetch — контролируемым ответом. Это не model-weight inference и не реальные provider/network calls. Windows/native квалификация не выполнялась. Main запускает `npm run check` и installed-archive `pack:check` перед интеграцией.

Нового независимого набора источников нет. Для будущего DEV планируется тот же раскрытый набор из 40 случаев; повторное использование набора не является независимой проверкой и должно быть явно указано в отчёте. QUAL требует отдельного зафиксированного допуска и независимого корпуса; результаты раскрытого QUAL нельзя использовать для выбора другого кандидата.

Последний учёт бюджета остаётся прежним: 239 физических вызовов и 75 case-arm; известные расходы — USD `0.14494101499999998`, неизвестный резерв — USD `0.24`. Будущий лимит — до 400 физических вызовов для DEV и до 1200 для QUAL при глобальном потолке 2000. Стоимость, лимиты вызовов и срок `2026-11-02T12:11:51.738Z` не менялись. В authored-scope cost proof исправлена только привязка `profileId` к новому кандидату и заново вычислен его `proofSha256`; сами цены, provenance цен, control identity, call caps и deadline остались прежними. Никакие новые вызовы, расходы, регистрация исследования, qualification, продвижение, MCP-интеграция или публикация этой записью не выполнялись и не разрешаются автоматически.

Будущий DEV использует тот же раскрытый набор из 40 случаев; это не независимая проверка. Для продолжения обязательны отдельные review 8/12 и полный DEV40 closeout. Только успешный DEV gate допускает новый замороженный независимый QUAL120; раскрытые DEV/QUAL данные нельзя использовать для выбора другого профиля. Mask-derived box и пиксельный IoU остаются разными проверками.

План исполнения, правила фиксации и остальные исторические результаты остаются в [плане качества 0.3.0](../0.3.0-quality-plan.md). Фиксированное описание политики и prior replay не редактировались.
