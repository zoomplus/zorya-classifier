# H8a: продолжение проверки карты LinCity

## Проверяемая гипотеза камеры

Закреплённый upstream LinCity-NG `a6101294b519db53489db8c3fac3e7a240722983` после загрузки сохранения ограничивает начало камеры с учётом размера окна. В `src/lincity/loadsave.cpp:612–617` используется формула `100 - floor(размер_окна_в_пикселях / 16) - 1`. Для 1024×768 предел равен `(35,51)`, что совпало с прежними перезагрузками. Для 800×600 предел равен `(49,62)`, поэтому сохранённые игрой камеры трёх выбранных входов должны пережить повторную загрузку.

Это ошибка проверки, а не повод переиспользовать квитанцию как успех.

## Гипотеза и ограниченный рецепт полного кадра

Новый этап должен сохранить ровно выбранный полный кадр основного SDL window renderer через `SDL_RenderReadPixels` до соответствующего `SDL_RenderPresent`. Ожидается 800×600 и `SDL_PIXELFORMAT_RGBA32`: это ровно 1 920 000 байт в порядке байтов RGBA, без масштабирования, обрезки, дорисовки, скрытия UI или изменения состояния игры. Наблюдатель пишет один файл с `O_EXCL`, `O_NOFOLLOW` и правами `0600`; квитанция фиксирует размеры, формат, кадр, результат чтения, байтовую длину и SHA-256. Анализатор отдельно проверяет длину и хеш, строит PNG из тех же байтов и сравнивает все декодированные RGBA-пиксели с исходным буфером.

Нативный захват включается только отдельным `--capture-native-frame` вместе со строгим `--require-metadata-gate`; стандартный режим остаётся метаданным. Успех метаданных не означает успех захвата: отсутствие или неверность нативной записи проваливает только новый capture gate и остаётся явной ошибкой в квитанции.

Первый замороженный манифест `native-frame-recipe-v1.json` сохранён вне репозитория с SHA-256 `03fd51479714f767f62c21c726484127daaa523c8b63d4f390dff405ee8fae53`. Независимая проверка обнаружила в его коде пропуск: запись `RendererEntry.surface == NULL` сама по себе не исключает, что SDL window renderer направлен в offscreen texture, и верификатор не проверял порядок всех событий полного кадра. Этот рецепт сохранён как неподходящая для запуска версия и не перезаписывается.

Исправленная версия `native-frame-recipe-v2.json` находится там же, вне репозитория, SHA-256 `d7e7040b270f612ed0e676724a8643f904cbd5ded11bd26351373c42a4d78ff0`. Она дополнительно требует `SDL_GetRenderTarget(renderer) == NULL` и в квитанции проверяет порядок `target draw < readback < render_present < capture_complete` для одного renderer. Счётчик кадра у `render_present` и `capture_complete` ожидаемо на единицу больше pre-present номера у target draw/readback. Встроенный fixture проверяет отказ для offscreen target.

Манифест v2 задаёт ровно три последовательных запуска в прежнем порядке: один Pottery, один Market, один Water tower. Для каждого используются то же сохранение, SHA-256, камера и lineage-квитанция из v2, 800×600, действие камеры `none`, предел 30 секунд, отдельный процесс и ровно один выбранный кадр. При первой ошибке выполнение прекращается; повтора, замены входа или движения камеры нет. Вызовы модели/провайдера запрещены. Полные RGBA и PNG остаются только во внешнем каталоге результатов.

SDL dummy fixture с известными пикселями проверил полный кадр, размеры, window renderer, отсутствие offscreen target, хеш, длину, режим файла, ошибку записи и запрет перезаписи. Затем рецепт v2 выполнил ровно три захвата: Pottery, Market и Water tower. Все три процесса закрылись; строгая мета-проверка и нативный capture gate прошли. Сохранения и камеры остались неизменными, модель и провайдер не вызывались. Квитанции, trace, исходный RGBA и побайтно проверенный PNG находятся во внешнем каталоге `/root/.codex/artifacts/zorya-classifier-mcp-20261101/lincity-resume/`. Сводка запусков `native-frame-run-batch-v1-summary.json` имеет SHA-256 `b569ed4a6a5d057ed69f0cd9d6a59b0b23e15b805cc1077572a3ea85fa270b15`; независимый аудит байтов и порядка trace `native-frame-output-audit-v1.json` — `b86f0592da2cbcc1777e904c9f3c65a1c58bb271e4c11d986357e3584996501f`.

После захватов анализатор стал явно считать `native_frame_capture` записью чтения, а не отрисовкой. Это не ослабляет учёт незнакомых событий: в тесте `render_geometry` по-прежнему остаётся нераспознанным. Повторный анализ тех же сохранённых trace дал ноль нераспознанных событий отрисовки для всех трёх кадров; возможные прямоугольные пересечения остались `14/11/20`. Первоначальные квитанции и trace не изменялись. Повторный анализ зафиксирован в `native-frame-analysis-replay-v2.json`, SHA-256 `d21da77fa1c489b6fd729aa539833e00addfc9e357bcfff199849822ee936e68`.
