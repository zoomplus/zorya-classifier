# v0.3 spatial-selection research proposal

Status: research and experiment design only. No source change or accuracy claim is made here. This proposal should be reviewed before implementation. Before each implementation step, state the exact hypothesis, files/contracts to change, and bounded validation plan; do not silently expand from a winning DEV result into a different method.

## What the evidence says

The current region locator in `src/processes/locate.ts` scans a full source region with a coarse cell pass, refines selected cells through multiple panels, and ends with a four-candidate crop comparison. It sends the original scene as context and derives every coordinate from code. `gridQuestions` in `src/features/prompts.ts` already asks for a closed top-four ranking, and `candidateQuestions` has an explicit `none` choice plus an independent binary presence question. The optional proposal locator in `src/processes/proposal-location.ts` also has a closed `none` choice for mask-derived boxes. Any new method must preserve these useful controls and must not turn `none` into whole-image absence or uncertainty.

The frozen 80-case v3 heldout run found seed cells in 26/60 positive cases, all intersecting the reference target box, but only 8/60 mask-derived whole-object boxes passed. It returned no seed on any of the 15 positive controlled map cases. Across all positives it ended with 35 unknown, 27 not-found, and 2 failed outcomes; among 20 negatives it had no false seeds or extractions. On the 30 photo cases with reference masks, 20 seed cells hit foreground, 11 predictions were scoreable, and 8 reached IoU 0.8; 19 had no predicted mask. The seed metric remains a search proxy, not localization. See [the heldout report](../evidence/v02/region-seeded-heldout-v3/README.md) and its [frozen evaluation summary](../evidence/v02/region-seeded-heldout-v3/evaluation-summary.json).

Prior evidence argues against unchanged prompt and grid variations. The native outline-plus-fixed-16 boundary presentation matched 1/23 evaluated positive instances (0/7 negatives falsely localized); the later checked-region DEV candidate matched 6/30 positive boxes even after a successful seed-search comparison. The v2 region-seeded candidate likewise matched 5/30 boxes. Six text-only image representations matched 0/16 positive photos and 0/7 positive UI cases. Earlier seed-point segmentation produced 5/30 boxes and one false seed on a negative; GrabCut on the same seeds produced 0 passing boxes. These results do not prove every mark, zoom, or tiled presentation fails, but they do rule out claiming that another outline, prompt wording, fixed interval grid, or seed-mask backend alone addresses the recall gap. See [outline-axis evidence](../evidence/v02/fresh-native-outline-axis/evaluation-root-v1.json), [DEV v1](../evidence/v02/region-seeded-dev-v1/README.md), [DEV v2](../evidence/v02/region-seeded-dev-v2/README.md), and [text-only trials](../evidence/v02/fresh-text/README.md).

## Research basis and limits

- [Set-of-Mark prompting (Yang et al., 2023)](https://arxiv.org/abs/2310.11441) studies alphanumeric and visual marks over regions generated at multiple granularities to make regions easier for a VLM to refer to. The [authors’ repository](https://github.com/microsoft/SoM) is a reproducible primary implementation. This supports testing explicit aliases over spatial candidates; it does not establish that labels help this caller-selected model or that fixed grid cells are the right regions.
- [LLaVA-UHD (2024)](https://arxiv.org/abs/2403.11703) describes dividing native-resolution images into variable-sized slices and retaining a spatial schema. This supports comparing a full-scene view with detail views that retain coordinate transforms. It is an architecture-specific result, not evidence that arbitrary extra image parts improve this library’s providers.
- [SAHI (Akyon et al., ICIP 2022)](https://arxiv.org/abs/2202.06934) reports sliced inference for small-object detectors and describes gains on aerial-image benchmarks. The official [SAHI repository](https://github.com/Small-Object-Detection/SAHI) implements overlapping slice inference and merges detections. This motivates testing overlapping tiles where small targets disappear at global scale or are cut at tile edges; its detector results do not transfer directly to a VLM selection pipeline.
- [VisionTrap (Saadat et al., 2025)](https://arxiv.org/abs/2507.17262) evaluates unanswerable visual questions and reports that choice options can increase answer-seeking rather than abstention. This is a reason to keep a true `none` candidate and separately measure false selections. It is not evidence that adding `none` alone will fix recall or calibrate this API.
- [Reliable VQA: Abstain Rather Than Answer Incorrectly (2022)](https://arxiv.org/abs/2204.13631) formalizes the coverage/risk tradeoff for abstention. It supports reporting correct localization and false-localization/abstention together, rather than optimizing positive coverage alone.

These sources support hypotheses and measurement choices, not guaranteed improvement.

## Ranked hypotheses

1. **A bounded zoom-and-tile fallback can recover false spatial absence.** When the coarse pass says no candidate contains a visible target, or returns spatially unknown, run one fallback comparison using the intact original plus a small, overlapping, aspect-preserving tile set. The tile geometry is code-generated and mapped to source pixels. Each tile remains a proposal region, never a whole-object box. Ask for a closed candidate ID or `none`; keep whole-image presence/absence independent. Hypothesis: some current `not-found`/`unknown` positives, especially small or map targets, become valid seed candidates without increasing false locations. Expected cost: one additional model request and more image tokens on fallback cases; expected risk: tile-boundary duplicates and increased false positives. This differs from the existing fixed non-overlapping grid refinement because it adds a bounded second look after a failed coarse scan, overlaps boundaries, and retains source context in the same decision.

2. **Marked multi-scale candidate sheets can improve spatial choice when coordinates exist but aliasing is weak.** For already-generated candidates, show a clean full source and a limited number of detail crops/tiles with stable alphanumeric marks linked to exact source rectangles. Compare the current crop/rectangle presentation against a Set-of-Mark-style candidate sheet while keeping candidate geometry and prompt semantics fixed. Hypothesis: better alias-to-region correspondence improves correct candidate selection and full-box coverage, particularly where several similar regions compete. Expected cost: increased presentation size and possible label occlusion; expected risk: the marks change visual attention or are misread. This is not another seed outline: the intervention is a consistent mapping among multiple regions, aliases, and zoom views.

3. **Small-object scale should be controlled by source-space coverage, not one universal tile size.** Compare a short, predeclared set of overlapping tile layouts (for example, full view plus 2×2 and 3×3 views) only on the fallback branch, using the original source in every candidate request and exact inverse transforms. Hypothesis: one additional scale recovers targets that remain too small in 2×2 views, while overlap reduces boundary misses. Expected cost grows with tile count and candidate count; expected risk is redundant context and poorer selection when many nearly identical aliases appear. The experiment should reject 3×3 if it adds cost without positive-case rescue or if it raises false locations.

The first hypothesis has priority because the strongest observed loss occurs before segmentation: many positives have no located seed at all. The second is only useful after there is a plausible candidate set. Do not combine hypotheses in the first comparison; measure the fallback geometry before changing its visual marks.

## Proposed implementation contracts (not yet authorized as code)

The likely implementation surface, subject to a fresh plan before each code change, is:

- `src/processes/locate.ts`: add a bounded fallback branch before converting an unsuccessful first spatial scan into terminal `not-found`/`unknown`; preserve the existing top-four ordered candidate contract and independent presence decision.
- `src/features/choice-beam-layout.ts` or a new focused feature module: define deterministic overlapping tile geometry and deduplication in oriented source pixels. Validate positive, in-ROI rectangles and safe dimensions. Do not infer coordinates from model text.
- `src/features/prompts.ts`: only if the selected experiment needs a distinct request schema; retain closed supplied IDs, `none`, and a separate binary presence predicate. A `none` answer means no candidate in the displayed union, never absence from the full source.
- Existing `RasterPort` preparation path and tests: present the complete source plus bounded crop views without stretching, preserve aspect ratio, record transforms, and respect transport image-size limits. Do not send arbitrary rendered PNGs directly to provider adapters.
- Benchmark/evaluator files: create a new frozen, independently named DEV profile and report outcomes by photo/UI/map stratum, with positives, negatives, unknowns, failures, physical fetches, cost, and latency. Keep mask-derived box accuracy separate from seed-cell hit rate.

No public contract change is proposed yet. The output remains the existing located source rectangle or a typed unknown/not-found result. The `none` choice never generates coordinates; a single-label final result remains one closed ID. Preserve raw categorical answers and do not introduce a universal probability threshold.

## Fail-fast experiment matrix

First compare only H1 against the unchanged frozen DEV recipe on the same predeclared DEV cases, using the explicitly configured Luna Decisions route and the existing no-fallback discipline. Do not call a provider or download weights during the research stage. Keep the established maximum of six physical calls per case, the development phase cost cap, and the complete case denominator; allocate the fallback request inside that cap before dispatch. Use an initial diagnostic slice of eight preselected DEV cases (six positive failures/unknowns and two verified negatives) only to reject obvious failure modes. Continue to the complete DEV set only if at least one positive case is recovered as a valid seed, neither negative gains a false seed, and no transform/protocol/resource invariant fails. The slice is a stop rule, not a qualification claim.

| Stage | Comparison | Keep fixed | Stop / proceed rule |
| --- | --- | --- | --- |
| 0: offline geometry | Tile generation, inverse transforms, deduplication, bounded image presentation using synthetic fixtures | No provider calls; no truth in producer payload | Stop on any out-of-bounds, missing source transform, broken overlap, or image preparation limit |
| 1: bounded DEV diagnostic | Existing locator vs H1 fallback on eight preselected DEV cases | Model/provider, prompts outside fallback, source bytes, classification/presence policy, timeouts, no retries/fallback | Stop unless at least one positive seed is recovered and both negatives remain seed-free |
| 2: full DEV pair | Frozen baseline vs H1 across all 40 DEV cases | Exact cases, truth, decision route, extraction/segmenter, call/cost caps, evaluator, score thresholds | Proceed only with complete receipts and no negative false seed/extraction; report full-object box scores separately |
| 3: H2 ablation | Existing candidate sheet vs stable-alias multi-scale sheet, only if H1 has a measurable seed benefit | Candidate masks/rectangles, candidate union, model/provider, question, ordering and budgets | Reject if candidate accuracy/box coverage does not improve or false selection increases |
| 4: H3 scale ablation | 2×2 vs 2×2+3×3 fallback, only if H1 survives | Everything except tile scale | Reject if added calls/tokens do not recover additional positive seeds while preserving negative gates |

Freeze the next comparison before dispatch. Require all-case completion, report paired per-case gains/losses and confidence intervals, and use whole-object mask-derived boxes as the primary localization endpoint; seed overlap is secondary. Do not inspect heldout outcomes to choose a tile scale, prompt, or candidate layout. A new candidate must pass a separately frozen DEV selection before any heldout plan is prepared.

## Expected tradeoffs and decision

The fallback should spend more requests only when the initial spatial pass is inconclusive or negative, so its cost depends on failure frequency and cannot be predicted from the heldout summary alone. More tile coverage may improve target visibility while reducing global context; including the original in each comparison is intended to preserve instance identity. Overlap can prevent a target from being split at a tile seam but also creates duplicate aliases. A closed `none` option can limit unsupported coordinate choices, while research on unanswerable VQA warns that multiple choice can itself bias models toward selecting an answer; both effects require measurement.

Recommendation: prototype H1 geometry offline first, then run the bounded DEV diagnostic only after its code plan, request identity, physical-call budget, and failure accounting are frozen. Do not start H2/H3 or claim improvement from the literature. The evidence currently supports a testable recall intervention, not an accuracy guarantee.
