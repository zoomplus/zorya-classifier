# H2c semantic proposal pilot runner

This is a benchmark-only, paired DEV12 execution recipe. It compares the frozen point-and-expand MobileSAM segmenter with the semantic seed-center proposal wrapper, using identical classifications, target text, source images, explicit Luna/OpenAI decisions, and the existing three-pass full-image seed search. The only candidate-specific change is how the original seed is converted to an extracted mask; there is no zoom mapping or app-level change.

The runner accepts injected factories for classifiers, baseline segmenters, candidate seed-center proposals, and the semantic wrapper. It never imports evaluator code or truth. It loads only the pinned opaque `loadV03PilotCorpus` manifests, verifies the frozen image bytes, alternates baseline-first/candidate-first by pair index, and executes one profile at a time for each case. Each profile has a 72-dispatch, $4 budget with a $0.05 unknown-charge reserve; each case/profile has a hard six-dispatch cap enforced at admission. The existing region-seeded case processor supplies the 120-second case deadline, classification-first behavior, three region passes, and canonical mask/cutout persistence.

The CLI defaults to dry-run. Dry-run verifies manifests, images, MobileSAM assets, and a complete local source-closure digest without opening a provider or initializing the native model. Paid execution requires the explicit `--allow-paid` flag and a configured API key. Candidate proposal lifecycle belongs to the runner; the semantic wrapper may settle/dispose its own work but cannot dispose the injected proposal port. The runner settles and disposes every native port once, even on failure.

From the repository root, dry-run with `node --import tsx benchmarks/v03/run-semantic-segmentation-pilot.ts --images <image-root> --output <output-root> --encoder <encoder.onnx> --decoder <decoder.onnx>`. Each invocation writes its plan before model initialization or API calls. A reviewed live invocation adds `--allow-paid` and reads `OPENROUTER_API_KEY`.

Before any dispatch, the run plan records the frozen cohort hashes, asset hashes, source closure, alternating order, route, budgets, and recipe identities. It rehashes the same closure after all outputs close and marks the run invalid if any member changed. The output contains per-case results, call receipts, masks/cutouts, profile budgets, and an immutable completion record. Evaluator/truth access happens in a separate post-run command and is outside this producer.
