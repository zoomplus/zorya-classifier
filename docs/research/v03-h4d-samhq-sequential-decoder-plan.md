**Status:** this separate, memory-bounded recipe is fixed before its second inference attempt. It keeps the H4d model, source, all boxes, prompt order, token selection, and mask threshold unchanged. Only decoder scheduling changes: one full-source encoding is cached once, then the 36 prompt decodes run serially.

## Same H4d hypothesis, sequential schedule

Keep the H4d protocol from [the SAM-HQ plan](v03-h4d-samhq-ui-box-refinement-plan.md): `syscv-community/sam-hq-vit-base` at revision `f906a2e3f60fda2f12eb717cef18614f66c43124`; same already verified external checkpoint, Apache-2.0 license, runtime, 1280x800 screenshot, same H4a output/freeze, and all 36 source-coordinate boxes in the exact frozen order. Use only `hq_token_only=True`, `multimask_output=False`, and the same zero-logit mask threshold. Do not introduce new prompts, box changes, candidate scoring/ranking, mask clipping, or truth access.

The supported Transformers `SamHQModel.get_image_embeddings(pixel_values)` returns both the image embeddings and intermediate vision features; this method and `forward` are part of the [Transformers v4.57.3 SAM-HQ implementation](https://github.com/huggingface/transformers/blob/v4.57.3/src/transformers/models/sam_hq/modeling_sam_hq.py). The retry will use the official preprocessor once with the full source and all 36 boxes to establish the unchanged transformed box tensors and size metadata, then call `get_image_embeddings` once. It will pass the same cached `image_embeddings` and `intermediate_embeddings` into 36 serial `SamHQModel.forward` calls, each containing exactly one consecutive transformed box. Thus every prompt sees the same full-source encoding and the same model recipe while prompt-decoder activations are bounded to one box. It must produce one source-size binary mask for every input ordinal, or fail the whole run; no candidate can be silently dropped.

This scheduling adaptation has its own freeze and output identity under `.run/v03/h4d-samhq-ui-box-refinement-sequential-v2/`. The producer is `benchmarks/v03/h4d-samhq-sequential-decoder.py`. The freeze records `decoder_batch_size: 1`, `image_encoding_calls: 1`, and `decoder_calls: 36`, all exact input identities and hashes, the old failed-attempt receipt hashes for provenance, fixed model/token/mask settings, producer hash, runtime, and 240-second owned-process-group deadline. The output refuses existing paths. After inference, it rehashes all source/H4a/model/license/script inputs and reports unchanged status. Record actual worker peak CUDA allocated/reserved memory and process maximum RSS.

The outputs remain full-source binary PNG masks, named and mapped to original `proposal_ordinal`, H4a flattened `flat_index`, score, and prompting box. Derive bounds and area from actual pixels; retain empty masks. A later independent evaluator alone joins the new frozen result to exposed labels using the same H4a gates. No model quality score enters selection.

## Limits and stopping rule

This is an engineering retry for an OOM, not a tuned accuracy variant. The only recipe change is prompt scheduling after one image encoding; all 36 prompts, their order and all semantic/spatial settings are identical to the failed frozen attempt. Keep the H4c result at 1/3 positive mask-bound availability as a separate unchanged comparator. If this retry completes, report every case and candidate; if resource failure repeats, retain the error and stop this route. The source is one controlled Geany image with styled colored button borders and cannot support general UI claims. No source integration, paid calls, dependency changes, downloads during inference, or automatic model loading are allowed.
