# Предварительная гипотеза: оракул LinCity-NG

## Гипотеза до диагностического запуска

Круговая реконструкция сохранения v3 сохраняет 54 пары «тип/координаты», но сама по себе не доказывает, какой объект нарисован в кадре. Проверяемая гипотеза: ограниченный observer на реальном SDL пути сможет связать заранее выбранную запись сохранения с конкретным texture draw по source-проекции координаты, RGBA-пикселям установленного ресурса и границам одного полного render/present кадра. Если эта связь или полнота видимой области не устанавливается, источник нельзя допускать как DEV-кейс.

## Зафиксированные входы и ограничения

- LinCity-NG `2.10.2-1`, source commit `a6101294b519db53489db8c3fac3e7a240722983`.
- Входное сохранение `main-lincity-roundtrip-v3/data/lincity-ng/quicksave.scn.gz`: SHA-256 `2cf706e580e7181bb1dc66f45d4e4c043b296249e18dcade022f2ae5ad22ad6f`; v4 round-trip использовал его как input и после настоящей загрузки/повторного сохранения сохранил 54 типизированные координаты и camera origin `(26,45)`. Скриншотов и model calls не было.
- `Farm` на `(32,50)` — диагностическая цель, выбранная по сохранению до чтения нового render output. Это не corpus case и не утверждение о visibility.
- Pinned upstream excerpts: `GameView.cpp` (`2ea15613218b0cd205f3fed4bbedabdd39c3169504a6555bd5cd9c43efba5a76`), `xmlloadsave.cpp` (`2be958dcd82b87d1d870a5927ee6421fa564ffb6a0147f9a70f3150e5c98d92d`), `PainterSDL.cpp` (`68dbd15bc1ecc19dd94cd12ac98855c5091bd9f56633e5cfac6ba4312a076442`), `TextureManagerSDL.cpp` (`05da5dc6d3a20cafadc22bc893c27a7e4c1d6b67188e8fcd3b35557c42e48c1d`). Их provenance закреплён в внешнем `fresh-dev/source-preflight/source-receipts.json`.
- В upstream source видно, что `GameView::drawTile` выбирает `ResourceGroup`/frame и вызывает draw на фактическом `Painter`; `PainterSDL` передаёт текстуру в SDL draw calls и заканчивает обновление через `SDL_RenderPresent`. Проекция из `getScreenPoint` зависит от source tile, viewport и настроек terrain height. Save file — gzip с собственным построчным/шаблонным parser; это не обычный XML документ.
- Context7 lookup для SDL в этой среде недоступен. Реализация должна опираться на зафиксированные source excerpts и локальные SDL headers, отмечая пределы такого preflight.
- Пакетный asset-аудит установленного `lincity-ng-data` закреплён в `fresh-map/main-installed-art-rights-v1/receipt.json` (SHA-256 `34cb3b925dd68bf79c92acb8e382ab1e6f6f9ef20f24403a4a879ec70d789d11`). Он подтверждает соответствие установленных файлов Debian source paths и copyright clauses, но не утверждает, что каждый ресурс был показан в кадре.
- Для пяти кадров группы `Farm` используется индивидуальная PNG- и decoded-RGBA-проверка из bounded локального аудита. `images.xml` SHA-256 `876f302b9815d7adf120837c13b5710ee1e30894135b7f2292ceccb646961392`; `COPYING-data.txt` SHA-256 `a1ba0d4def4f09c484388a84f7bb3d804e259ad92079022ff772b0e080987821` заявляет dual license GPL и CC BY-SA 2.0. Установленная ссылка `fonts/sans.ttf` ведёт на DejaVu Sans из `fonts-dejavu-core 2.37-8`; отдельный font receipt оговаривает, что пакетная атрибуция не доказывает использование конкретного glyph в кадре.

## Предполагаемая проверка

1. До запуска проверить bounded gzip/save metadata и exact input digest; записать typed construction coordinates, viewport origin и save version, не импортируя их в producer manifest.
2. Запустить ровно pinned game package в приватных user/network/PID/mount namespace, с приватным XDG profile и динамическим Xvfb display. Использовать только копию исходного save. Не читать/создавать screenshot, не запускать provider/model и не менять/пересохранять исходный файл.
3. После Continue создать приватный control-marker. Observer сначала ждёт точного draw для замороженного диагностического Farm resource/hash и source-projected destination; только после такого readiness он записывает один следующий полный кадр между двумя `SDL_RenderPresent`. Startup trace остаётся выключенным, лимиты trace/байтов/времени остаются жёсткими. Отсутствие readiness, неполная пара frame markers или достижение лимита дают `unresolved`.
4. В выбранном кадре сверить target texture, alpha extent, destination, clip и последующие draw bounds. `SDL_RenderFillRect` трактуется как `(x,y,width,height)`, polygon bbox — как half-open `(x0,y0,x1,y1)`, а line bbox строится из двух концов. Неизвестные последующие события сохраняются как возможные overlays; неизвестный texture hash не считается прозрачным. Overlap report остаётся консервативным кандидатом на overdraw: прямоугольное пересечение само по себе не доказывает, что поздний draw реально закрыл пиксель target. Observer не перехватывает все возможные SDL draw API, поэтому отсутствие кандидата на пересечение не заменяет ручной просмотр кадра.
5. Записывать ограниченный trace, package/source/resource hashes и все ошибки только во внешний artifact root. После прогона доказать закрытие именно собственных процессов и очистить лишь точные созданные profile/temp пути.

## Сохранённые диагностические результаты

- v1 завершился до запуска приложения из-за неверного input-save digest/path. v2 сохранил timeout/ошибку незакрытия процесса после того, как preload observer не был связан с SDL2. v3 загрузил и сохранил только приватную копию, но observer не начал trace из-за отсутствующей инициализации. Все эти внешние артефакты сохранены; они не являются случаями корпуса.
- v4 реально загрузил сохранение и завершил приложение с закрытым owned process group. Trace observer зафиксировал 18 803 `render_copy`, 48 `render_present` и 109 различных decoded texture digests, затем достиг общего лимита 50 000 событий. Пост-обработка нашла 14 одинаковых target draws по save coordinate `(32,50)`, Farm group 5 и точному decoded RGBA fingerprint `farm0.png`: ожидаемый и фактический destination `[320,448,512,512]`, frame index 34–47. Alpha bbox ресурса после viewport clip — `[320,695,832,768]`. Trace был общим и достиг cap; поэтому кадр/видимость/occlusion не считаются доказанными. Ошибка `failure.json` отражает превышение лимита строк парсером, а сохранённый trace и отдельный post-analysis оставлены неизменными.
- Следующий diagnostic вариант переключает запись только после control-marker и подтверждённого exact target draw, затем закрывает trace на следующем `SDL_RenderPresent`. Это должно удержать полный один render frame в небольшом trace без изменения игры, save, textures или screenshot. Этот запуск ещё не выполнен и требует отдельной проверки main.
- Первый v5 с этим механизмом сохранил точный target draw и полный выбранный кадр, но тест выявил, что marker повторно запускал запись на последующих кадрах: receipt содержит 13 capture windows и 24 753 события. Этот артефакт сохранён как неуспешный ограничитель объёма, не как доказательство одного окна. Исправление переводит capture в одноразовый режим и анализатор отдельно отвергает trace с несколькими окнами; повтор v6 ещё не выполнен.
- v6 подтвердил target draw и полный кадр между двумя `SDL_RenderPresent`, однако trace содержал 9 окон из-за повторной активации всё ещё существующего marker после каждого завершения. Анализатор верно пометил его как не прошедший контракт единственного окна. В v7 добавлен terminal latch; v6 и его receipt остаются неизменными.
- v7 успешно записал ровно одно окно: 1 904 события, 714 051 байт, один `capture_start`, один `render_present` и один `capture_complete`; process group закрыт, screenshot/model calls — 0. В этом полном SDL frame снова подтверждён Farm `(32,50)`, group 5, frame size candidate 4 и точный `farm0.png` RGBA digest; source-projected и фактический destination равны `[320,448,512,512]`. После clip видимый alpha bbox `[320,695,832,768]` упирается в низ viewport. Observer отметил 20 пересекающихся поздних draw bounds; это возможные overlays, не доказанные закрывающие пиксели. Поэтому техническая связь save→draw установлена, но этот частично обрезанный target не подходит как целый unoccluded positive.
- v7 external receipt SHA-256 `3f2fabd3bccfd5829419fbac921be3480aa02fd862170e58ef02c0bb3cb0244d`; selected trace SHA-256 `0e0a46f1cdc8d02af63cb65e276e42cb40abefd0c30ad189a9be14835efed0d2`. Оба артефакта лежат в `fresh-map/luna-lincity-diagnostic-v7/`.
- В pinned `GameView.cpp` клавиши Up/Down/Left/Right меняют viewport через `scroll`; исходная v3 точка `(26,45)`. Оффлайн расчёт по `getScreenPoint` задаёт желаемые центры `(31,49)` для Farm `(32,50)` и `(41,49)` для Farm `(43,50)`. При точном canonical origin ожидаемые size-4 destinations соответственно `[256,160,512,512]` и `[320,192,512,512]`; соответствующие alpha bbox помещаются в 1024×768. Это расчётная цель, не доказательство захвата.
- v8 использовал настоящие Arrow Down/Right keydown/up на приватной сессии и сохранил camera origin `(31,49)` при неизменном inventory из 54 конструкций. Trace завершился одним окном и процесс закрылся, но фактические Farm0 draw rects были `[268,150,512,512]` и `[972,502,512,512]`, а не canonical projection. Сохраняем v8 как `unresolved`: `writeOrigin()` сохраняет целый tile center, а текущий in-memory scroll содержит дробную часть. Этот сдвиг не подгоняется по пикселям target.
- v9 загрузил v8 postrun save как отдельно закреплённый derived input в новом профиле без прокрутки. Независимая reload подтвердила inventory из 54 constructions и camera origin `(31,49)`. Trace содержит один полный present window; анализатор v2 нашёл точный набор соответствий Farm32/Farm43, но не устранил неоднозначность общего target `Farm`. v8 остаётся unresolved для точного smooth-pan совпадения; оригинальный save и v8 неизменны.

Ни один запуск не создавал screenshot, не делал provider/model call и не изменял исходное сохранение. Наблюдение draw не является corpus screenshot/case, не набирает DEV quota и не доказывает целую видимую форму. Для positive case позднее всё равно нужны ручной просмотр оригинального кадра, проверка полного target extent и source-to-screen mapping. Для negative case нужен полный inventory всего viewport; отсутствие одной target texture недостаточно. Даже успешный positive не устанавливает mask quality или classification quality.

До любого corpus capture остаётся подтвердить полный выбранный draw frame, отсутствие запрещающего overdraw, фактическое использование допустимых UI/font/icon ресурсов и точную связь source state с оригинальным кадром. Если bounded observer не закрывает эти связи без эвристики или изменений пикселей, результат остаётся unresolved и LinCity не получает DEV-слоты.
