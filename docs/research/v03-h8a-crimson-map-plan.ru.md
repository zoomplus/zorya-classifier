# Новый DEV источник карт: Crimson Fields

## Назначение и состояние

Этот отдельный H8a DEV источник заменяет квотно-непригодные три положительные и две отрицательные строки Lincity. Он состоит из одной игровой семьи Crimson Fields и пяти заранее зарегистрированных состояний. Это только DEV материал, не heldout-квалификация. Порядок и состав закреплены до кадров и ответов классификатора; отказ или нехватка допустимых строк не разрешают подменить сценарий.

Родительский протокол зарегистрировал порядок в `/root/.codex/artifacts/zorya-classifier-mcp-20261101/main-dev-map-order-v3.json` (SHA-256 `7971c99ab729703d51ddea894d57ac1f1e8ca2d0a48c24329a583a1274047b5a`). В этой версии положительные состояния — частные нативные сборки уровней с одним изменённым направлением одного выбранного юнита. Два отрицательных состояния остаются штатными уровнями ArmsRace и Baptism. Исправленный offline audit применяет реальный `HANDICAP_NONE` bitmask `0x01`, проверяет его байт в каждом `.lev` и реконструирует первичный unit inventory по точной очереди native events. До этого исправления v7 receipts были ошибочно интерпретированы как неизменённый source inventory; их физические наблюдения клиента и чтения `.lev` сохранены, но прежние map-state claims не используются.

**Приёмка завершена: все пять V11 кадров независимо проверены главным оркестратором и приняты в частный DEV набор.** SHA-256 private review receipt: `59ab2277384ee0d9a75ec231d2f439bede0a089acd66dbf8cc710f5c0081a100`. Каждый кадр прошёл source, native draw и exact pixel gates; run IDs, image и receipt hashes приведены ниже. Никакой классификации или model/provider вызовов не было.

Первый кадр серии V10 (только Anthill) сохранён, но gate отказал: `KP_2 --clearmodifiers` отправил SDL `KMOD_NUM`, а все 272 ожидаемых opaque source pixels не совпали с исходной 8-bit RGB-палитрой. Этот кадр навсегда исключён; оставшиеся четыре V10 строки не запускались. V11 сохранил тот же зарегистрированный roster и запросы, исправил input и добавил финальную проверку draw и точной SDL16→XCB таблицы. V10 не переиспользовался.

Ранее завершённый stock Anthill v4 metadata run отдельно подтверждает, что закреплённый клиент открыл штатный Anthill и прошёл оконные/процессные gates. Это не подтверждение viewport и не допуск кадра. Он также не устанавливает изменённое startup inventory. Старые stock-положительные сценарии не возвращаются в roster: их штатные направления пересекались с полосой здоровья и не давали чистого эталонного спрайта.

Пакетный `debian/copyright` указывает GPL-2+ с перечисленными исключениями. Шрифт `Bepa-Roman.ttf` имеет отдельную лицензию Bitstream Vera и свои условия сохранения уведомлений. MIDI не участвует в изображении, звук отключён. Перед любым кадром должны быть проверены точные байты и права фактически отображаемых ресурсов: `default.tiles`, `default.units`, `cf.dat`, шрифта и уровня. Одного общего copyright-файла недостаточно.

Upstream source, лицензии и исходные уровни закреплены во внешнем каталоге `/root/.codex/artifacts/zorya-classifier-mcp-20261101/crimson-metadata-contingency/`. Частные facing-варианты лежат вне репозитория в `.../crimson-source-v1/facing-variants-v2/`; их manifest SHA-256 `63a952d69c5e0576954d246ae9e3f5a66dc09bbdc5404c90fbd9b3d1c403e873`. Каждый `.src` получен из соответствующего закреплённого сценария добавлением одной строки `face = N` в выбранный `[unit]`; stock `.src` и `.lev` не менялись. Закреплённый `cfed` успешно скомпилировал variants. Независимая проверка сравнила каждый бинарный `.lev` со stock: длина совпадает, различается ровно один байт направления — Anthill offset 10886 (`0→2`), BeachRaid 7590 (`0→1`), ClippedWings 12775 (`0→2`). Весь остальной source unit inventory совпадает.

Нативный `gamedefs.h` определяет `HANDICAP_NONE = 0x01`; каждый stock/частный `.lev` хранит этот mask в байте offset 15 согласно `Mission::Load`. Поэтому direct `--level` запускает именно сценарий «без handicap», но handicap events с mask 1, 3 или 5 всё равно совпадают и выполняются. Маски 2 и 4 не совпадают. `Event::CheckTrigger` сравнивает их через bitwise AND; трактовать no-handicap как нулевой mask нельзя.

Лицензионные игровые ресурсы и изображения остаются во внешнем artifact root; в репозиторий не копируются кадры, sprite bytes или частные игровые пакеты. В игре используется read-only распаковка и изолированное окно X11; никаких сетевых запросов, платных вызовов или изменений системы нет.

## Runtime и будущий pixel gate

Metadata launcher запускает закреплённый Crimson напрямую с `--level`, размером 800×600, оконным режимом и отключённым звуком. Для положительных строк bubblewrap подменяет только конкретный путь выбранного `.lev` read-only частной сборкой; остальные игровые данные остаются из штатного пакета. Для отрицательных строк используется закреплённый stock `.lev`. Xvfb выделяется через динамический display fd; и клиент, и каждый `xdotool` probe получают один и тот же адрес через allowlist. Окно должно быть отображённым, некорневым и принадлежать PID закреплённого ELF. Если UI не доказывает окно, точное чтение выбранного `.lev` или активную карту, результат — отказ.

Для проверки renderer извлечён официальный `libsdl1.2-dev` 1.2.68-2 (80 652 байта, SHA-256 `42f2799c0f5ac96f314797fdcfe90765849a6ad5389bde5b71d4be74ed448a7d`), а также только распакованные GCC/binutils и их отсутствовавшие runtime/development части. Все скачанные клиентские/runtime/SDL/compiler пакеты вместе занимают 41 548 198 байт (39,63 MiB из лимита 40 MiB); все распакованные игровые, SDL и compiler файлы занимают около 136,5 MB из лимита 200 MiB. Пакеты, toolchain, tracer и fixture находятся только во внешнем artifact root; системные пакеты и глобальная конфигурация не менялись.

Source inventory хранит единицы мира, владельцев, IDs и гексы; перевозчики и их груз следует трактовать как отдельные объекты. Прямой `--level` запускает без handicaps, то есть с `HANDICAP_NONE=1`, а не с нулевым mask. `Game::InitWindows` выполняет handicap pre-start events; затем интерактивный `StartTurn` показывает turn note, включает карту и вызывает `CheckEvents` в time 0. Oracle сопоставляет source-порядок с native `.lev` event queue: по размеру `Event::Save`, полям event id/type/trigger/dependency/discard/flags/player и trigger value. Затем моделирует все active `createunit` events по порядку, проверяет пустые unit/building hexes, присваивает IDs как `Mission::CreateUnitID` и проверяет все due-now timer events и `settimer` delays. Так получаются точные post-initialization inventories 150/67/67/62/217 для пяти строк. Anthill event 8 добавляет вторую жёлтую артиллерию; ClippedWings events 8/9 добавляют две артиллерии; Baptism events 31/32 добавляют два Gunships. Baptism timer-zero events 0 и 14 заблокированы `flags=1`, а остальные createunit timer events зависят от этих корней; oracle закрепляет весь dependency graph и отказывает при включении корня или отсутствии ожидаемой зависимости.

Metadata gate теперь требует точное чтение native PID выбранного `.lev`, совпадение с полным source-simulated post-start inventory, точный target selection и complete native event order. Это доказывает roster truth, но не означает, что видимый экран уже является bare map. После штатного Return для turn note остаётся одно player-1 timer-zero message event в каждом сценарии. До capture заранее закрепляются два Return ввода всего: первый закрывает turn note, второй — единственное интерактивное turn-zero сообщение; затем короткое фиксированное ожидание и проверка окна/процессов. Никакого условного повтора или неизвестного нажатия до кадра не будет. Metadata receipts сами по себе имеют `screenReadyForCapture=false`.

На metadata этапе framebuffer и screenshot не читались. Статический atlas gate теперь сам декодирует pinned gzip-ресурс `default.units`: проверяет custom surface header на offset 3518, palette/raster boundary 3907, 768×336, 8 bpp, palette из 126 цветов, colorkey `(210,2,252)` и точное соответствие независимому source-audit. Для выбранных tiles 26/229/158 oracle вычисляет полные raster masks: 272/286/246 непрозрачных пикселей, half-open bounds `[4,3,27,23)`, `[4,3,27,24)`, `[6,3,26,23)` и нулевое пересечение полосы здоровья `[12,23,20,27)`. Это проверяет исходный атлас; фактический draw и экран всё ещё требуют отдельного native run.

Viewport закреплён source-трассой: `Game::InitWindows` создаёт MapWindow размером всей 800×600 поверхности; `MapView::Enable` обнуляет offsets; `StartTurn` находит первый юнит игрока 1, вызывает центрирование и затем включает cursor. Native integer projection берётся только из `MapView::Hex2Pixel`, `TileSet::DrawTile` и размеров 32×28 со сдвигами 9/14. Offline camera simulation по каждому `.src` и полному post-event inventory вычисляет начальные offsets; Anthill после обычного центрирования имеет `[0,64]`, а BeachRaid `[0,0]`, ClippedWings `[0,50]`, ArmsRace `[0,0]`, Baptism `[83,1030]`. Эти значения проверяются против pinned размеров карт, `CenterOnHex`, `CheckScroll` и границ viewport.

Для Anthill обычный целевой гекс (14/23) выходит за нижний край при начальном offsets. V10 использовал `KP_2 --clearmodifiers`, но независимый SDL/Xvfb input fixture показал `SDLK_KP2` с `KMOD_NUM=4096`; native `Game::HandleEvent` отправляет такой ввод в `MoveCommand`, а не `ScrollCommand`. V11 заранее фиксирует один `xdotool key KP_Down` без `--clearmodifiers`: тот же fixture после двух точных Return получил SDL key symbol 258 (`SDLK_KP2`) с `mod=0`, что соответствует `ScrollCommand`. Это одна навигационная команда, без дополнительного выбора объекта. Источник и результат fixture сохранены в `/root/.codex/artifacts/zorya-classifier-mcp-20261101/crimson-source-v1/input-diagnostic-v3/receipt.json`, SHA-256 `47eac85c7cb3b3dbfead775d43664750903e9a88a7a43047e545702784f8c74d`. По pinned `ScrollCommand`, `SetCursor` и камере курсор перемещается с (7/12) на (7/24), camera offset достигает нижней границы `[0,114]`; target tile тогда проецируется в `[322,530]`, opaque mask — в `[326,533,349,553]`. Остальные положительные targets после StartTurn целиком в viewport: BeachRaid tile `[23,294]`, mask `[27,297,50,318]`; ClippedWings tile `[138,314]`, mask `[144,317,164,337]`. Экранные координаты не подгоняются по кадрам.

V11 планирует пять отдельных снимков той же зарегистрированной семьи и использует те же source states и neutral queries. Для каждой строки сначала нужно доказать PID-owned mapped XID, завершённое чтение правильного `.lev` и активную карту. План фиксирует inner native argv, capture environment, read-only tracer bind и полный список `xdotool` ввода. Ровно два `Return` закрывают turn briefing и единственное интерактивное player-1 timer-zero message; после Anthill-сценария следует ровно один source-verified `KP_Down` scroll. Фиксированное ожидание — 1000 ms; одна съёмка на сценарий; условных нажатий, retries и замены строк нет. На ArmsRace отрицательный anchor — player-1 Medium Tanks ID3 на гексе 5/2, face2, atlas source `[64,0,32,28]`; на Baptism — Medium Tanks ID1 на 32/48, face5, source `[160,0,32,28]`. Icon 0 подтверждён pinned `default.usrc`; anchor gate сверяет именно этот source tile и полный native draw, а pixel gate — всю его непрозрачную маску.

Native draw witness — частный `SDL_LowerBlit` interposer, собранный из `native_blit_trace.c` точным приватно распакованным compiler/toolchain. Его файл подмонтируется read-only отдельным sibling `/opt/crimson_blit_trace.so`, вне read-only directory runtime libraries. Он сохраняет bounded JSONL blit rectangles к viewport и вызовы keyed unit-atlas surface (768×336). Trace ограничен 2 MiB; ошибка записи, переполнение, отсутствие стартовой записи или barrier закрывают gate. После фиксированных UI-действий и ожидания runner требует barrier и проверяет trace. Положительный gate выбирает последнюю запись для ожидаемого source→destination преобразования; если после полного blit того же target обнаружен обрезанный/неполный фрагмент, строка закрывается. Отрицательный gate закрепляет конкретный native source tile Medium Tanks face2/face5 и также требует последнюю запись полного размера на named anchor. После одного XCB readback байты tracer и status должны совпасть с состоянием на barrier. V10 показал, почему раннего совпадения недостаточно: его trace содержал поздний укороченный blit другого экземпляра face2 по нижней границе.

Отдельная capture-функция делает один RGB `ImageGrab` XCB readback заданного окна 800×600, сохраняет PNG эксклюзивно во внешнем artifact root и связывает digest с XID/native PID. Положительный пиксельный oracle точно сравнивает RGB всех opaque source-atlas pixels в целевом tile с закреплённой SDL16→XCB таблицей; converted colorkey index 0 прозрачен. Для отрицательных строк проверяются все 245 opaque pixels named anchor. ArmsRace local `(19,23)` сравнивается с source-proven black outer healthbar border `[0,0,0]`; остальные 244 значения сравниваются с таблицей. Baptism сверяется по atlas во всех 245 точках. Любой несовпадающий RGB байт закрывает строку. Каждый PNG остаётся исходным 800×600 RGB без resize/crop, а вся маска находится в viewport. Main вручную проверяет полный кадр, включая fog, cursor, health, UI и соседние объекты. Admission и создание private DEV rows остаются за main; если кадры будут допущены, `referenceBoxes`, `referenceMasks` и `exactOriginalCanvasMaskRef` фиксируются в frozen schema.

```text
px = hex.x * (TileWidth - TileShiftX) - curx + viewportX
py = hex.y * TileHeight + (hex.x & 1) * TileShiftY - cury + viewportY
```

Размеры тайла и сдвиги берутся из закреплённых игровых ресурсов; подгонять камеру или проекцию по цели в кадре запрещено.
