# H4c: SAM2 refinement of frozen UI detector boxes

**Status:** protocol fixed before the H4c model run. The H4a box output remains immutable. This is a bounded producer-only mask availability experiment; it makes no provider calls and does not select masks using evaluator truth.

## Hypothesis and rationale

H4a retained 36 class-agnostic OmniParser boxes on a controlled Geany screenshot. Its best box for each of three positive buttons reached IoU 0.8458–0.8957 and target coverage 0.8458–0.8957, narrowly below the predeclared coverage gate of 0.90. H4c asks whether passing those same proposals as box prompts to SAM2 yields full-source masks whose actual foreground extends to the visible control boundaries. The H4a result remains recorded as 0/3 under its original box gate; H4c is a new hypothesis and does not revise that measurement.

The UI image is a controlled Geany screenshot containing styled, colored button borders. This is not evidence of generalization to natural UI screenshots, other applications, themes, or devices.

## Official model behavior and pinned resources

The official SAM 2 image predictor accepts a box in XYXY pixel coordinates, reshapes its two corners into prompt points with labels 2 and 3, and sends those prompts to the mask decoder. It postprocesses masks to the original image dimensions. Thus the detector box conditions the segmentation prompt; it is not a crop/clipping boundary. H4c will request one mask (`multimask_output=False`) and retain that full-source binary raster. See the [official SAM2 image predictor](https://github.com/facebookresearch/sam2/blob/main/sam2/sam2_image_predictor.py), including `predict`, `_predict`, and `postprocess_masks`.

Use the already staged `facebook/sam2-hiera-tiny` Transformers checkpoint at revision `7c218beaf0bb87874785f32b582f640134fc1c09`, Apache-2.0 per the [pinned Hugging Face model card](https://huggingface.co/facebook/sam2-hiera-tiny/tree/7c218beaf0bb87874785f32b582f640134fc1c09). The existing local `model.safetensors` is 155,841,672 bytes, SHA-256 `1449035ba6ba2ed524c646da989e5cb3a9b93b97f1c1b2d474e598c3b748d99f`. Adjacent pinned config hashes: `config.json` `3239c7ecf212b1a9d9f98310c8993612335c5596a12c8cfba25e512e9dc5965b`; `preprocessor_config.json` `6ebf229ee259368ce4a8d4f2fe893a72b053023710853e257253939e601f583d`; `processor_config.json` `f8a68e865cfad115c1c2763f3d93eca7b1c622da06da2a9273eb437fb2389b6d`. Before model load, create an exclusive (must-not-exist) output leaf under ignored `.run/v03/h4c-sam2-ui-box-refinement-v1/`. After inference, re-hash every input and script and record unchanged status in `run.json`. Refuse to reuse or overwrite any historical output path.

Save each output as a full-source binary PNG mask (`0` background, `255` foreground), named by stable proposal identity, e.g. `candidate-000-mask.png`. `run.json` maps every retained mask back to the exact H4a row using `proposal_ordinal` (0-based frozen order), `flat_index`, raw detector `score`, original `box_xyxy`, mask path/hash/byte size, source width/height, mask pixel area, emptiness, actual mask-derived bounds (minimum inclusive x/y and exclusive maximum x/y), model quality output as an explicitly uncalibrated diagnostic, and timing. Require exactly one output for each of the 36 rows; keep empty masks and inference failures visible rather than silently dropping them. Store no duplicate source pixels and commit no `.run` contents.

## Evaluation and interpretation

Once the producer output, post-inference integrity record, mask hashes, and `run.json` are frozen, an evaluator-only process may join the masks against existing exposed truth. Preserve every candidate and all negative outcomes. Report per-positive best candidate only as an availability diagnostic, alongside all 36 candidates and the unchanged H4a mapping. Use the same H4a predeclared box gate (IoU at least 0.50 and target coverage at least 0.90) on mask-derived bounds for a comparable availability count, while separately reporting pixel-mask overlap if already defined by the evaluator. Never describe an oracle-best mask as production selection or accuracy. The absent Undo case remains included for false-positive/proposal-availability context; proposal presence is not a semantic decision.
