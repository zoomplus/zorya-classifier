# v0.3 segmentation quality research plan

**Status:** research plus two bounded development mechanism screens. No production source changes or heavyweight model dependencies were made. The second screen used five caller-configured Luna/OpenAI Choice calls against already exposed development photos; results below are diagnostic evidence, not an independent qualification or a promise of accuracy.

## Recommendation

Run the first low-cost experiment against the already pinned CPU MobileSAM encoder/decoder, comparing its existing one-center-point path with a small number of semantically grounded prompt variants and retaining every decoder mask. Use the existing five independently masked public development photos for this component screen, then use the full frozen development set only if one variant has a plausible signal. This needs no paid calls, new model weights, or new npm dependency. Keep the official mask annotations evaluator-only and inspect all outcomes, including empty/invalid-seed cases; do not manufacture a foreground point from the annotation.

If this prompt ablation plateaus because locator seeds miss the target, the next route should be an optional, caller-owned text-grounding segmenter adapter (first benchmark SAM 3 on a few exposed development images, without integrating its runtime). SAM 3 is now an existing official model and combines text concepts with visual prompts. Its official install currently requires Python 3.12+, PyTorch 2.7+, a CUDA GPU, and checkpoint access approval; this makes it a useful GPU-backed alternate experiment, not a library default or a suitable package dependency. If its model license/access or GPU deployment is unsuitable, test crop-based multi-scale MobileSAM over caller-provided candidate boxes as the fallback. Keep the caller's `DecisionPort`, provider and `SegmentationPort` injection points unchanged.

## What the local evidence says

- The current `createMobileSamSegmenter` is already caller-owned and optional. It requests explicitly supplied encoder/decoder paths and an execution provider; importing the package does not download or choose weights. The current native prompt implementation sends either a single seed center encoded as a positive/negative point pair, or the whole-region box; it filters masks to the ROI and, in the seed mode, to masks that intersect the seed. SAM's four decoder masks are produced, but current segmentation collapses them to the highest decoder-IoU diagnostic candidate. See `src/infrastructure/segmentation/mobile-sam/{index.ts,worker-inference.ts}` and `src/infrastructure/segmentation/native-worker.ts`.
- On the paired five-photo component set, MobileSAM's supplied-box component reached mean per-case IoU 0.859 and 4/5 cases at IoU >= 0.8 when run with oracle-derived interior seed centers. The original Hat seed had zero reference foreground, and the original Cat seed center was background. This shows the quality ceiling under supplied geometry, not an available seed-generation method or end-to-end performance. The same report gives GrabCut 0.595 mean IoU and 0/5 at IoU >= 0.8 on the oracle-corrected panel. See `benchmarks/experiments/segmentation-component-comparison-2026-10-20.md`.
- The nine-point MobileSAM proposal universe contains useful masks for some instances but does not fix the primary missed-seed cases: in the offline five-photo replay, one photo had zero of nine prompt points hitting either of two annotated instances; a second had zero of nine for one of two instances. Best proposal IoUs reached >=0.8 for only 3/6 annotated instances across four seeded images. In the 40-case proposal DEV2 evaluation, positive whole-object boxes matched only 1/30; the earlier DEV1 had 3/30. The evidence therefore argues against simply increasing the fixed point count or promoting the current proposal route. See `docs/evidence/v02/dev2-mobile-sam-proposal-oracle.md` and `docs/evidence/v02/dev2-proposal-evaluation.md`.
- In the actual five-case expansion run reviewed for this task, none of the five expanded cases was rescued (5/5 failed to yield an accepted strict superset). The current native expansion surface is `SegmentationPort.expand` in `src/entities/segmentation.ts`; the soak harness explicitly rejects an expansion that does not add foreground while preserving every prior foreground pixel (`benchmarks/v02/region-segmentation-resource-soak.ts`). Do not center another quality plan on forcing a decoder to return an enclosing strict superset: SAM's predicted mask is a boundary hypothesis, not a monotone grow operation. The checked-in 4df544c resource receipt demonstrates stability and lifecycle only, not that expansion improves mask quality.
- Region-seeded DEV v1/v2 each matched 5/30 positive whole-object boxes; one independently annotated mask reached IoU >= 0.8 out of seven. v1 also had a false negative-case extraction; v2's class-presence gate fixed that specific failure mode, not the positive localization rate. These results distinguish upstream grounding/localization from contour quality and set the need for separate box and mask metrics. See `docs/evidence/v02/region-seeded-dev-v1/README.md` and `region-seeded-dev-v2/README.md`.

## Ranked hypotheses

### 1. Better use of the existing MobileSAM decoder prompts and multimask output

**Hypothesis.** For a correctly grounded target, a small structured prompt can produce a mask that better follows its visible boundary than the current single center point. Positive points must come from already available, caller-owned cues (for example, a seed anchor and the center of a separately supplied candidate box); negative points must come from an explicitly supplied exclusion or a reviewed background point. Never derive a positive point from ground truth, image color, an assumed object center, or a post-hoc mask. Keep the full-source coordinates and ROI clipping.

The official SAM task supports foreground/background point sets, boxes, masks and multiple disambiguating masks. A 3x3 set of arbitrary positives is not the proposal here: it repeats the failed nine-point direction. Compare at most three interpretable profiles: current prompt; supplied box plus one seed positive; supplied box plus seed positive and one explicit negative cue. Record every returned mask and score its mask IoU and mask-derived box separately, then use the injected `DecisionPort` only in a separately budgeted end-to-end experiment if an actual multi-candidate selection stage is proposed. The decoder's IoU score stays an uncalibrated diagnostic and cannot select the semantic object by itself.

**Cost/risk.** No new weights or JS dependencies; reuses the local MobileSAM assets and one image encoder. More decoder prompts cost additional CPU/GPU time, but should be small compared with introducing a second model. Current ONNX export accepts point prompt arrays, but this must be verified against the pinned graph and worker protocol before implementation. Poor/contradictory negatives can erase true foreground. A larger mask count can improve the oracle-best ceiling while making actual selection harder, so report both best-candidate ceiling and deployable selected-candidate performance without conflating them.

### 2. Optional caller-owned text grounding with SAM 3

**Hypothesis.** Text concept grounding can replace or augment the weak locator seed when the target can be described with a short noun phrase, potentially addressing part-versus-whole and visually similar instances before contour selection. The experiment should pass only the caller's target phrase and source image to the explicitly selected segmenter; it must not send evaluator labels or invoke a hidden classifier/provider. For SAM 3's returned instances, preserve source-space masks and boxes, then retain existing closed box containment verification and whole-object selection policy.

SAM 3 is confirmed to exist: Meta's official repository exposes text/visual prompts, returns masks/boxes/scores, and documents 848M parameters. Its current README requires a CUDA GPU plus Python/PyTorch versions above, and gated checkpoint access. The official repository names its own SAM License; this is not Apache-2.0. Review that license and the checkpoint grant in full before redistribution or product deployment; do not bypass access approval. The model is large and GPU-oriented, so do not add its runtime to npm or download its weights automatically.

**Cost/risk.** Highest operational cost of these hypotheses: gated model files, CUDA and Python process, GPU memory, additional deployment surface, and model-specific license review. A few local development images can establish feasibility before any API budget or integration. The current hardware profile (RTX 4080 16GB with approximately 13GB free; approximately 25GB RAM available) is enough to plan a local screening run but is not itself evidence of fit or accuracy. If the library ever supports this, use a separately packaged adapter behind the existing caller-supplied segmenter port or an external process boundary, requiring explicit checkpoint/provider/configuration from the caller.

### 3. Crop-based multi-scale MobileSAM for small or missed foreground objects

**Hypothesis.** For UI/map and small-object misses, re-encode a bounded set of candidate crops at native crop resolution and map each predicted mask back through a recorded crop transform. This may help when an object occupies too few pixels in the single full-image encoder input. Crop proposals must be supplied by the existing locator or a caller-owned detector/grounder; do not add game/UI/color heuristics or infer object bounds from labels. Keep an explicit hard source ROI and require a valid seed/candidate intersection. Include all crop/mask attempts in budget and timeout accounting.

This is a generalized route for photos, UI and maps without relying on a photo-only vocabulary detector, but it multiplies encoder work and can miss objects if candidate boxes are poor. A native automatic-mask generator such as SAM's automatic generator or MobileSAMv2 object-aware prompt sampler could generate region proposals for comparison, but these are proposal generators, not semantic instance selectors; their candidate count and memory cost would require a separate profile. FastSAM is not preferred for integration: the official project requires PyTorch and checkpoint setup, and the repository currently carries an AGPL-3.0 license marker while its README has differing model-license language. Resolve code/model terms before use. Grounded SAM's official recipe adds GroundingDINO plus SAM and multiple separately licensed/model assets, so it is a heavier alternative to the SAM 3 single-model screen.

## First experiment: a cheap prompt ablation

Use the same five public annotated development photos and pinned MobileSAM assets already used by the paired component report. Freeze the exact input images, seed, ROI, whole-region box, graph hashes, execution provider, thresholds and evaluator source manifest before inference. Keep the historical original seed as the primary condition; the oracle-derived foreground-center panel may be included only as a clearly separated upper-bound component diagnostic. Do not let the reference masks affect prompt generation, candidate selection or payloads.

Compare: (A) current one-center seed prompt; (B) whole-region box plus current seed point; (C) that same box/positive point plus one negative point only where an exclusion/background cue is already present in the current caller input. If the current public input has no valid explicit negative cue, skip C rather than synthesizing one. Return and persist all decoder outputs per prompt profile before opening truth; do not discard losing masks.

Report, by case and aggregate, valid-seed rate, seed-intersection/coverage, exact-canvas mask IoU and reference coverage, mask-derived box IoU and coverage, empty-mask rate, decoder calls and monotonic duration. Include all five cases and keep the zero-foreground Hat seed visible; separate valid-grounding component results from the full denominator. The key test is whether prompt B improves masks beyond A when the seed intersects truth, without increasing masks that violate the seed/ROI constraints. This is a cheap mechanism test, not a product-quality conclusion. If positive signal appears, compare against the frozen development control using the existing corpus discipline, then freeze and qualify on untouched heldout data before promotion. Do not read revealed heldout misses to invent another profile.

For the optional SAM 3 feasibility screen, use at most 5 previously exposed development images spanning photo, UI and map, one short target phrase per case, the same masks/box criteria, and no hidden truth in the request. Record checkpoint revision, license/access state, VRAM/RAM peaks, latency and all returned instances. Stop after this screen if installation/access, footprint, or source-category failure is unacceptable; do not pay for hosted calls.

### Prompt-probe outcome

On the fixed five-case panel, the native score-picked point-seed masks averaged IoU `0.6350` and the evaluator-only oracle-best masks averaged `0.9205`. Adding a seed-centered box fixed at 3× the cell performed much worse: `0.1556` native-selected and `0.2604` oracle-best IoU. All four candidates hit each seed, so that profile did not fail from missing the seed; reject it rather than tuning its box size against this tiny panel. The probe reproduced existing v3 point-seed masks exactly on cases 01 and 16. On cases 02 and 18, the highest MobileSAM diagnostic score selected a part mask (IoU `0.258` and `0.068`) despite a lower-score full-object candidate (IoU `0.787` and `0.964`). These two gaps motivated the separately frozen semantic-selection mechanism screen.

### Closed semantic-selection screen outcome

The five frozen requests each included the original photograph plus four point-seed MobileSAM candidate presentations labelled A–D, with one closed Choice over A/B/C/D/none. The exact target phrase and full-object criterion were sent; evaluator masks, IoUs, case IDs, seed geometry and scores were not sent. The caller-configured `openai/gpt-6-luna-decisions` route returned five valid choices in five physical calls, without retry or fallback; receipts reported `$0.0020205` total cost and no unknown-cost calls. The semantic choices selected a mask with mean IoU `0.9133`, compared with `0.6350` for MobileSAM's native score choice and `0.9205` for the evaluator-only best candidate. Per-case IoU was: 01 Horse native D `0.938`, semantic D `0.938`; 02 Bird native B `0.258`, semantic C `0.754` (oracle D `0.787`); 04 Cat native C `0.970`, semantic C `0.970`; 16 Truck native D `0.941`, semantic D `0.941`; 18 Camera native B `0.068`, semantic D `0.964`. The selection layer repaired both large native-versus-oracle failures on this deliberately diagnostic panel, but this panel was selected because the point-seed masks already exposed those gaps and is not independent evidence of general improvement.

The v1 presentation renderer placed a 42-pixel candidate label strip over the top rows of every image rather than in an added margin. Post-response evaluator-only inspection found that it occluded 1,280 Cat-reference pixels in case 04 (`0.50%` of that reference mask), and none on the other four cases. This is a presentation flaw and possible bias; preserve the result as-run and do not reuse that renderer for qualification. The next composition should put labels outside the source raster, retain an unmodified original view, and record the image transform. No extra calls were made to repair the frozen screen.

The reproducible local runners are `benchmarks/v03/segmentation-prompt-probe.ts`, `benchmarks/v03/evaluate-segmentation-prompt-probe.ts`, `benchmarks/v03/semantic-mask-probe.ts`, and `benchmarks/v03/evaluate-semantic-mask-probe.ts`. ### Planned implementation screen: opt-in seed-center MobileSAM proposals

The next local component experiment will use the existing `ObjectProposalPort` and native worker, with no new public port or classifier composition. Add an explicit `sampling: 'seed-center' | 'seed-grid'` option to `createMobileSamObjectProposals`; preserve the existing nine-point grid as the default for back compatibility. The opt-in seed-center strategy sends exactly the geometric center of the actual seed cell as one positive point, reuses the pinned full-source encoder once and calls the decoder once, then returns all four decoder masks in stable `C00`–`C03` order as packed masks. Keep native quality scores diagnostic; do not let the worker select or semantically rank a mask. The unmodified nine-point route must continue to return 36 masks in `C00`–`C35` order.

Thread the new option through `src/infrastructure/segmentation/mobile-sam/index.ts` and the strict `mobile-sam-proposals` request validator in `src/infrastructure/segmentation/native-protocol.ts`; consume it in `src/infrastructure/segmentation/mobile-sam/worker-inference.ts`. Allow only the two exact proposal counts in the reply validator and check the count/profile against the caller's parsed option before returning. Update focused worker/protocol tests in `test/mobile-sam-proposals.test.ts` and `test/native-protocol-base64.test.ts`; do not edit `src/app/create-classifier.ts`, proposal location, presentation ports, entities, public exports, package dependencies or defaults.

The experiment must prove that one center prompt is source-bounded and returns exactly four valid packed planes, that ROI and alpha clipping remain enforced, and that a malformed/non-finite decoder tensor fails closed. Existing proposal ownership tests already establish that a DecisionPort is not called until `propose()` settles and that cancellation retains the classifier slot until the physical proposal promise closes; the existing native-child tests establish owned-child close and cancellation capacity retention. Re-run these focused lifecycle suites after the option change. This is only a proposal mechanism integration step: the parent's later frozen composition owns label-outside-canvas presentations, the existing 3-choice localization path and one semantic Choice plus closed-box checks. Do not make a paid call or use evaluator truth to select this native profile before that composition and its call/cost budget are frozen. If the H2c end-to-end screen plateaus due to seed/candidate recall, return to the optional SAM 3 text-grounding feasibility route rather than expanding fixed point counts or forcing strict-superset masks.

### Frozen execution plan: closed semantic selection among point-seed masks

This follow-up is justified by the prompt probe's two obvious native-versus-oracle gaps (case 02: IoU 0.258 vs 0.787; case 18: 0.068 vs 0.964) and uses no new segmentation inference. Before dispatch, freeze the exact five case IDs, input manifest/photo hashes, target strings, existing point-seed four-mask files and hashes, the complete probe/evaluator source hashes, presentation renderer, prompt, Decision request, and one explicitly configured Luna Decisions/OpenAI caller route. The `DecisionPort` and provider are a caller-owned research recipe; there is no library default or hardcoded production model/provider. Do not modify prompt/profile or choose cases after seeing answers.

For each case, send one source image plus four full-source-size candidate presentations A-D in a single closed Choice. Each candidate view preserves the original image, aspect ratio, full visible target pixels and context; render the mask as a semi-transparent color fill and bright contour at its full-source location, with its A-D identifier burned into a fixed label strip. Do not crop to the mask. The request asks for the entire visible requested object, not merely a part, and excludes unrelated instances. Options are exactly A, B, C, D, and `none`; ties use the existing stable raw-argmax behavior. No second Noul, retry, or fallback is allowed. Save the actual selected alias and provider receipt, then only after all five responses are immutable may the evaluator inspect the already exposed masks. Report the model's native choice and the separately computed truth-IoU oracle candidate; never transmit evaluator truth, scores, case aliases, or target-mask geometry.

Run one physical Decision call per case maximum (five total) with a $1.00 hard budget and $0.05 unknown-cost reserve. Preflight every source and rendered image against source hash, dimensions, byte/pixel limits, and immutable hashes before enabling dispatch. Keep raw presentations/receipts in ignored `.run/v03/`; publish only non-image summary evidence and hashes in docs. This selected, known-exposed DEV panel is a mechanism diagnostic, not independent proof of general improvement.
