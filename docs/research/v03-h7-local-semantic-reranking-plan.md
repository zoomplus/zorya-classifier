# H7: local semantic reranking of a frozen mask pool

Status: accepted benchmark-only shadow experiment, recorded before asset staging, implementation or inference. H6's candidate views are retained as a useful development result, but H6 is not qualified: 6/9 positive whole-object results, 0/3 map successes and false locations on all three negatives. Its presence question admitted every case. The new experiment does not claim to solve absence by thresholding another model's score.

## Hypothesis and research

H6 can expose a correct mask while losing it at nomination or final selection. Instead of another atlas-prompt rewrite, H7 tests a distinct mechanism: encode each actual candidate's pixels and compare that representation with the authored target. [SigLIP 2](https://arxiv.org/abs/2502.14786) studies image/text retrieval and improved visual representations. [Global-Local Context RIS](https://arxiv.org/abs/2303.17811) motivates preserving context when matching masks to expressions. Conversely, [mask-adapted CLIP](https://arxiv.org/abs/2210.04150) warns that ordinary image/text encoders can perform poorly on masked images. These sources motivate a falsifiable shadow test, not an expectation that a new encoder must win.

## Fixed recipe

- Same H5a v2 source images, twelve authored targets, D/U pools, ordering, pinned binary masks and immutable evaluator truth as H6. All families are processed on every case. No OCR, captioning, source/game labels, extra target descriptions, native quality ranks, truth-driven crops or source replacement.
- Explicit operator-owned checkpoint `google/siglip2-base-patch16-512` at revision `a89f5c5093f902bf39d3cd4d81d2c09867f0724b`, Apache-2.0. Stage only the necessary official files under the existing external model-assets directory, never npm or the repository. Record immutable upstream revision, file sizes and actual SHA-256 values. The known safetensors file is 1,503,344,520 bytes, SHA-256 `fe0e601c625e69eed8e73500d39e9b6164403fe03db8048e87913c3cefbbb3fe`. Review the small configs before executing existing Transformers code. No remote code, automatic fallback or downloads during inference.
- Existing isolated Python 3.12 / Torch 2.6 CUDA 12.4 / Transformers 4.57.3 environment; standard `SiglipModel`, explicit CUDA device, float16, evaluation/inference mode. Do not add `accelerate` or use an implicit device map. If the pinned runtime cannot execute the fixed recipe, retain the failure before proposing a repair.
- Each candidate has two views from the same source-coordinate context rectangle: a clean crop and the crop with pixels outside its actual binary foreground replaced by RGB (128,128,128). Derive the rectangle by extending the actual foreground bounds by 25% of their width/height on each side, rounded outward and clipped to the source. This fixed context fraction follows the earlier proposal presentations; do not search it against truth. Neither view contains aliases, a grid or drawn mask colors.
- Fit each view into 512 by 512 with preserved aspect ratio, deterministic centered gray padding and a fixed bilinear resize. Feed the resulting image through the pinned processor's normal normalization. Record resize geometry. Encode the full authored target exactly once per case using the checkpoint tokenizer. Reject a target that exceeds its text limit; never silently truncate it or substitute a head noun.
- L2-normalize each visual embedding and the text embedding. Score a candidate as the arithmetic mean of the two cosine similarities. Record both components and their mean without converting them to probabilities. Rank all actual candidates by this mean; stable ties use D before U and original ordinal. Also report per-family ranks diagnostically. No learned combination, threshold, calibration or per-stratum routing.
- Preserve every candidate and empty family. At most 36 per family, 72 per case; decode/process in batches of two candidates (four visual views). Retain packed masks, not all decoded source-sized masks or tensors. Cache nothing across cases beyond the loaded encoder/tokenizer. Maximum owned CUDA allocated memory is 10 GiB; record allocated and reserved peaks separately.
- One explicitly owned worker, one encoder load, 120-second initialization deadline and 240-second absolute deadline per case including pixel preparation, encoding and serialization. Join physical child exit on cancellation; do not release capacity while it is running. Reuse the existing owned-worker lifecycle. No external model/API calls. Freeze the plan, source closure, source/assets/input identities and recipe before inference; rehash after completion. Preserve all twelve rows including errors and timeouts.

## Outputs, evaluation and stop rule

Write a separately named H7 shadow run outside the repo with per-candidate source mask hashes, aliases, crop transforms, raw score components, stable ranks, timings, runtime versions and memory measurements. Scores only nominate candidates. Negative rows remain `not-a-presence-decision`; do not report zero false detections merely because this experiment makes no final detection claim.

The independent evaluator joins each ranked ID to the already verified actual mask receipt. Report top-one and top-four availability separately for photos/UI/maps, all errors/missing ranks as misses, and compare with H6's frozen nomination/final losses. Report each negative's ranks and similarities without choosing a rejection threshold from its result.

Advance to a separately planned end-to-end composition only if H7 retains all three photos and all three UI positives in its global top four and retains both available map positives there. Prefer an actual top-one improvement with at least one map success; a rank-four ceiling alone is not final accuracy. If this criterion fails, retain H6's measured positive gain and pivot away from this encoder/view recipe. Do not retune crops, weights or thresholds and replay until a favorable result appears. Full DEV40 and the independent release gate remain required before promotion.

## Parallel ownership

- Native owner: pin and stage official assets, implement the bounded local shadow producer and pixel/normalization/ranking/cancellation tests in its own worktree. Reuse immutable H5a loading and current worker helpers; no public adapter or package dependencies in this phase. Run a small synthetic ownership/runtime probe before the frozen twelve-case run. The actual twelve-case inference requires root integration/source freeze first.
- Evaluation owner: finish and preserve the H6 audit, then add a small H7 score-to-mask receipt evaluator using the existing H5a truth evidence. No producer changes or truth access in the worker. Report stage ceilings honestly.
- Spatial owner: finish H6 post-run visual diagnosis of wrong-location versus object-part selections. Use the failure evidence and primary research to suggest the next spatial/absence mechanism; do not send new provider calls or alter H7's recipe.
- Root: owns this prospective plan, checkpoint authorization, asset-location choice, merges, frozen run dispatch, independent review and advancement decision. Models/assets remain explicitly supplied by consumers if a strategy is later promoted; this benchmark does not install or choose models for library users.
