## Состав пакета

`zorya-classifier-mcp` — отдельный MCP-адаптер для опубликованной библиотеки `zorya-classifier@0.2.3`. Версия самой библиотеки и её публичный API в рамках этой работы не меняются. Зафиксированные зависимости MCP SDK: `@modelcontextprotocol/node@2.1.2`, `@modelcontextprotocol/server@2.4.0`, `@modelcontextprotocol/server-legacy@2.4.0`; для протокольных проверок используется `@modelcontextprotocol/client@2.4.0`. MCP-пакет использует Zod 4, библиотека — собственную Zod 3. Требуется Node.js `>=22.12.0`.

Сервер предоставляет шесть инструментов: `zorya_classify`, `zorya_locate`, `zorya_extract`, `zorya_get_job`, `zorya_cancel_job`, `zorya_capabilities`. Installed archive проверен SDK-клиентами для modern и legacy stdio, modern и legacy Streamable HTTP и legacy SSE. Векторы совместной работы job store между сессиями, owner isolation и физической отмены входят в consumer smoke.

Библиотека не выбирает provider или модель за пользователя. Оператор явно задаёт профиль, provider и необходимые секреты. Для extraction требуются отдельно предоставленные сегментатор и локальные runtime/assets; сервер не выбирает и не загружает веса автоматически. Обычные vision-модели и native decision — отдельные поддерживаемые маршруты. Ранжированный ответ не превращается в выдуманные вероятности.

Локализация сообщает координаты и ограниченную область просмотра; bbox или грубая область не объявляются маской сегментации или целым объектом. Extraction может вернуть только проверенную видимую маску. Неизвестный semantic result отделён от транспортных, backend- и resource-ошибок.

Jobs, результаты, uploads и артефакты живут в памяти процесса и удаляются по TTL или при завершении процесса. Секреты provider могут храниться в зашифрованном файле на POSIX-системах либо только в памяти по явной настройке. В режиме только в памяти секреты теряются после перезапуска. Файловый vault на Windows возвращает типизированный `UNSUPPORTED_OPERATION`; автоматического перехода на менее защищённое хранилище нет. Эти свойства относятся к локальным контрактам; эксплуатация в конкретной production-среде отдельно не проверялась.

2. Свежий независимый read-only аудит полной acceptance-матрицы с точным `APPROVE`, затем финальная проверка главным оркестратором.
3. Публикация `zorya-classifier-mcp@0.1.0` и byte verification опубликованного tarball после gates. Публикация ранее авторизована; новых запросов разрешения в рамках этой работы не требуется.

До получения конкретных receipts CI, review и publication статусы остаются `PENDING` в [плане приёмки](mcp-implementation-plan.ru.md). Локальные software gates не закрывают эти оставшиеся проверки.

## Воспроизводимые локальные команды

Для локального воспроизведения package gates на Node.js `>=22.12.0`:

```bash
cd packages/mcp
npm ci
npm run check
npm run pack:check
npm run docker:check
```

`check` запускает package secret scan, TypeScript, lint, 26 границ модулей, Knip, tests, build и Prettier. `pack:check` создаёт и проверяет реальный npm archive, устанавливает его в независимый consumer и запускает type/CLI/SDK smoke. `docker:check` собирает образ, запускает его под неповышенным пользователем с внешним runtime config и удаляет только принадлежащие ему image/container resources. Root-level checks и CI всё равно выполняются отдельно. Потребительские примеры установки и конфигурации доступны в [README пакета](../packages/mcp/README.md).

## Связь с H8a

H8a исследуется независимо. Его исторические receipts и оценки не являются MCP-предпосылкой, не входят в MCP quality gate и не заменяются этой документацией. В частности, никакое число автономно завершённых задач, offline фикстур или H8a DEV-прогонов не означает повышения точности модели. Полный контекст и матрица MCP находятся в [плане реализации](mcp-implementation-plan.ru.md).
