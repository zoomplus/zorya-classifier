# Region-seeded DEV v1: failed evaluation

This is an exposed development evaluation, not release qualification. The frozen gate failed: the run returned a seed region and mask for one verified-negative case, while the predeclared gate required zero false seed locations and zero false extractions. It also produced only 5 correct mask-derived boxes among 30 positive cases and only 1 passing exact-canvas mask among 7 references. The underlying results and denominators are preserved unchanged in the ignored run artifacts; this checked-in report contains aggregate metadata and hashes only.

The candidate used the original three-choice class decision, followed by a full-source MobileSAM seed-point prompt from the located region. It made no extent-search or same-instance confirmation calls. The recorded model route was `openai/gpt-6-luna-decisions`, with CPU MobileSAM. The no-image control used the same classification recipe and verified that all 99 checked requests contained no image parts. Neither model is a library default; both are benchmark-only caller configurations.

The 40-case DEV set contained 20 Open Images photographs, 10 controlled Geany UI captures, and 10 controlled Freeciv renderer captures. The UI set uses a known GTK style and an independent application/source-geometry oracle. The map set uses one controlled game family with source-state and renderer checks. These controlled strata do not represent natural user captures or diversity across applications and games. One Freeciv Fighter negative was classified as absent, but the pipeline still returned a seed and mask from unrelated map content; the absence label came from the complete controlled game-state inventory.

The seed-region metric is intentionally weaker than localization: any positive-area intersection with a reference box counts only as a coarse search proxy. The candidate found 18 such intersections across 30 positive cases and also found one region on a negative. Whole-object success is measured separately from the mask-derived bounding box using the frozen criterion of IoU at least 0.5 and reference-box coverage at least 0.9. That criterion passed 5/30 positives, with one false location among 10 negatives. All 40 rows remain in the denominator: 7 extraction outcomes were unknown and 8 failed.

The seven independent exact-canvas masks were all scored. One reached IoU 0.8; the other six did not. The remaining 35 cases have no reference mask and are unannotated for mask scoring, rather than counted as mask failures or successes.

The paired no-image comparison is limited to the 16 positive photo cases and the same coarse seed-box-intersection proxy. Its bootstrap interval does not measure whole-object localization. The separate GrabCut run reused the same 23 already-found seeds, with no new model calls. On the 22 available positive seeds, GrabCut produced 0 passing mask-derived boxes versus MobileSAM's 5 on that same subset; eight positive cases had no seed and stayed unavailable within the 30-positive denominator. Across the seven exact-canvas mask references, GrabCut had 0 IoU passes while MobileSAM had 1. This is component-only evidence, not a new end-to-end candidate or an alternative qualified recipe.

A post-hoc rule that suppressed extraction whenever the already-recorded classification said “absent” would remove this run's one negative seed and extraction while preserving the positive cases. That is only a diagnostic over the same recorded outputs. It is not a rerun, does not repair this failed gate, and is not counted as an eligible recipe.
