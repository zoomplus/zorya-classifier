# Fresh DEV vision profiles

The runner consumes only pinned producer input arrays and source images. It never imports evaluator code, ground truth, source ledgers, or heldout manifests. The photo and independent UI manifest SHA256 values are fixed in `run-fresh-dev.ts`; the image root is a separate argument. A future DEV stratum can be included only by adding its reviewed DEV input manifest and pinned hash.

For each case, the runner makes a closed-label `present`/`absent` classification and an independent whole-object localization request with 8-pixel tolerance and at most three extent passes. The research profiles are `native-numeric-v1` (public numeric baseline) and `native-seed-outline-axis-fixed16-v1` (whole-instance prompt, seed outline on the original, and rendered axis boundary views with fixed-16 interval choices). Each profile has its own immutable run, 250 physical-fetch/$5 budget, exact OpenAI native Decisions route, 45-second operation timeout, and no retry or fallback. Use `--profile` to launch exactly one frozen profile; without it, the CLI runs every registered profile. Concurrent-development latency is retained as evidence but is never ranking eligible.

Before any provider call, the runner loads all pinned producer arrays, rejects extra fields and duplicate IDs, validates every source image's containment, SHA256, format, orientation and dimensions, and checks that model-facing task objects contain no case ID, source path or source SHA. It writes a frozen run manifest with the planned IDs, image hashes and dimensions, manifest hashes, route, policy and source digests. It then reloads and verifies each image before dispatch, and zeroes the owned byte buffer after both operations.

The classifier receives only the task question/classes and image bytes. The locator receives only the target/instruction and image bytes; controller IDs, local paths and source hashes remain in the runner. Every planned case gets both stage rows, including preflight failures, operational errors and unknowns. The summary explicitly reports planned, completed and missing case IDs so interruption cannot silently shrink the evaluator denominator. Physical receipts and sanitized traces are stored beside each case result. Never open fresh truth or compute quality metrics in this producer task; freeze both profile summaries first, then use the separate evaluator.

Run offline fixtures with `node --import tsx --test test/v02-fresh-corpus.test.ts test/v02-fresh-runner.test.ts test/v02-fresh-cli.test.ts`. Dispatch only through `run-fresh-dev.ts` with explicit `--allow-paid` after checking both pinned runs and image roots.
