# Categorical HELDOUT run plan

This plan module freezes profile identity and per-run budgets for the next separate HELDOUT evidence runs. It does not open producer input files, images, evaluator truth, or dispatch provider requests. A caller must first verify the root-provided freeze file against its external SHA-256 pin, then pass the parsed plan through `buildHeldoutPlans` after root gives explicit dispatch clearance.

The candidate run must contain 40 photo, 20 independent UI, and 20 independent map inputs, and follows the target policy selected by the completed DEV comparison. It preserves the selected DEV recipe: 120-second operation deadline, two case workers, a shared native pool with one active worker and two waiters, two native threads, 8-pixel tolerance, and three extent passes. Its budget is 600 physical calls, $10, and a $0.05 reserve per unknown charge; six calls per case gives a 480-call upper bound. The no-image control is a separate 40-photo profile with the same selected target policy and a 300-call, $5 budget. It uses DeepSeek v4.1 Flash through Together with JSON Schema and reasoning `none`, and must remove every image part before dispatch. It uses no image encoder, proposals, segmentation, or OCR.

The photo manifest pin is fixed to `5d125e853ed93558ab634e406ca90cf931569953279c1630d49dcf239b9baa79`; the current canonical UI pin is `1bf7940fd92fdc1f7fa295296dfc5f84c5f4c32ccc41b7a2e80a0059bff918c3`. The canonical map input pin is `2c18d2c1bae481d0a1239802f32d4ac985bc0d33a028eaafb490fd5995de7a3b`. Previous source-oracle arrays are not accepted by this plan. The externally SHA-pinned strict freeze binds method selection `fabb05c2c472c30a8cb20a5f9b6d697b932d94aedc43976359746463ef8708b9`, exact input pins, and separate executable source digests for the candidate and no-image control. Extra fields are rejected rather than silently dropped. The selected policy is `target-plus-neutral-instruction-v1`; the freeze must name it explicitly.

Both producer summaries retain planned/completed/missing case IDs, per-case stage records, physical receipts with their owning case ID, the selected method digest, and explicit source-before/source-after digests. The no-image control also audits each serialized request immediately before its fetch, stores aggregate counts for zero image parts and zero image-derived state, and marks the run incomplete if a body cannot be checked or contains an image field or encoded image payload. Raw request bodies are not retained.

The original v3 setup failed before any provider call because every photo input used a different generic instruction. The [preserved zero-HTTP failure](../../docs/evidence/v02/categorical-heldout-predispatch-20261020-v3.json) and original freeze remain unchanged. The v4 producer-only derivative changes exactly the forty shared instruction fields to the selected DEV suffix, with all target/image/ID/truth values preserved; its separately frozen executable closure must be checked before dispatch. No prompt algorithm, model, scoring criterion, threshold or task target is changed.
