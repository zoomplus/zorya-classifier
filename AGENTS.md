# Zorya Classifier contributor rules

Canonical owner-wide policies live under `/root/.cursor/rules/` (repository cleanliness, Context7 for external SDK docs, and related). The supervisor must include applicable constraints in task prompts; Cursor does not automatically load home rules. Project pointers: [.cursor/rules/zorya-classifier.mdc](.cursor/rules/zorya-classifier.mdc), Russian workflow/architecture [docs/agents.ru.md](docs/agents.ru.md), [docs/architecture.ru.md](docs/architecture.ru.md), [docs/development.ru.md](docs/development.ru.md), wave status [docs/refactoring-plan.ru.md](docs/refactoring-plan.ru.md).

This repository is independent of Zorya Games. Implement the accepted MIT library plan in docs/plan.md.
For the current accuracy iteration follow docs/0.3.0-quality-plan.md. The owner authorizes testing alternative localization/segmentation mechanisms with internet research and a written hypothesis before implementation. Preserve v0.2 evidence and default API compatibility; do not treat the historical v0.2 primary flow as a prohibition on separately named benchmark experiments. Promote only a candidate that passes the new independent quality gate.
Use strict TypeScript and Zod at public/provider boundaries. No explicit any, unchecked external casts, broad lint disables, or swallowed rejected promises.
Layers: app composes; processes orchestrate features; features use entities/shared; infrastructure implements ports. Entities/shared never import infrastructure.
Use the explicitly configured model/provider, with no fallback. Ordinary vision language models must work without native classifier APIs. Rank-only answers must not be converted into fake probabilities. Native Choice scores are categorical: select a maximum, retain raw scores, stable input-order ties; no universal 0.8 gate. Preserve raw quantized probabilities and require the explicit adapter annotation/interval test for non-unit mass; never silently normalize scores. Noul presence is a separate binary decision. Never call cell geometry a segmented object.
Own input bytes before awaits. All async operations share one absolute timeout, honor cancellation, release timers/listeners and retain concurrency slots until physical work settles. Imports do not start background tasks.
Keep real-provider and offline evidence distinct. Ground truth never enters requests. No color/game heuristics, image fitting to known labels, invented negative labels or claims of universal superiority.
Do not copy .env, private media, chat/session logs, source history or unrelated dependencies. Paid diagnostics are explicit with hard call/cost budgets. Publication requires explicit owner authorization; respect existing session authorization.
Run npm run check and npm run pack:check. Update docs, provenance and benchmark evidence with behavior changes.

Secret hygiene: preserve the staged-blob scan in Husky and worktree scan in check/CI. Empty .env.example is the only environment template; templates are content-scanned too. Run pack:check against installed archive bytes, not only gitignore rules. Never print matching secrets, copy upstream credential files, or create broad test/documentation exclusions. Secret heuristics and ignore files reduce risk; they are not a proof that arbitrary data contains no secrets.

Single-label classification and final candidate selection require one closed ID. Only spatial beam stages require four ordered candidates. Never reject a valid single-label operation for missing unused alternatives or invent probability distributions from ranks. Preserve protocol variants and failed live evidence when changing this contract.

The library never selects or connects a model/provider on the caller's behalf: require an injected `DecisionPort` or an explicitly configured adapter. Model/provider names in examples and benchmark recipes are examples, not defaults. Do not imply that model strength guarantees monotonic accuracy improvement. Ordinary vision-chat and native decision routes are both supported. Native distributions retain original scores and must not inherit Jev-specific quantization without explicit evidence/configuration.

For v0.2 follow docs/0.2.0-plan.md. Default region behavior remains compatible. The primary extraction flow runs the original region locator, then prompts an explicitly caller-owned segmenter with the seed on the full oriented source image; derive bounds, center and cutout only from actual valid mask pixels. The owner's latest correction adds a closed post-segmentation containment check: send the full source with the actual mask-derived box and original seed anchor, choose complete/needs-expansion/unknown with the injected DecisionPort. `complete` yields the result (optional cutout); `needs-expansion` permits at most one enclosing-mask correction and one final check (a final `complete` can still produce the result); missing expansion support, no valid enclosing mask, failed final check, or other unresolved checks yield `unknown` with no second expansion. Expansion must preserve every prior visible foreground pixel and grow actual foreground and its box, within the hard ROI; never a stretched box. Do not add model-generated coordinates or an extent-search to this flow. A verified box is not proof of pixel-perfect segmentation. The optional legacy interval-boundary strategy uses closed integer intervals within the hard ROI; never infer hidden geometry, sort invalid bounds or call a grid cell a whole-object box. Seed and object regions must intersect.

Extraction is an explicit workflow with a caller-owned segmenter. Processes use ports; native/image implementations stay in infrastructure. Validate and own all external masks, metadata and decoded bytes before awaits. Only a valid visible source mask produces a transparent PNG; transport/backend/resource errors are typed failures, not semantic absence. Caller shutdown disposes both its classifier and its segmenter.

Full-source rendering and model-view preparation are separate stages. Route box-check presentations through the injected raster imageState preparation, as the original locator does: keep all source content and aspect ratio, record padding/scale, and retain original mask coordinates. Do not send arbitrary-size rendered PNGs directly to the built-in transports or relax their 280..1568 prepared-side validation. Test the real public native and ordinary adapters with controlled fetches; a bare DecisionPort fixture cannot detect transport preparation defects.

Candidate presentation must preserve source/mask pixel correspondence through crops, resizing and letterboxing. Never map the entire padded panel back to the source as if it were stretched. Construct clean/overlay/cutout in one source coordinate space and apply the same explicit transform, or account for the actual resized dimensions and offsets. Test landscape and portrait cases at the pixel level; output dimensions alone cannot prove alignment. Visible-instance extraction permits gaps caused by occluders and disconnected visible components; do not infer or require hidden object pixels.

Native adapters initialize only on explicit factory calls, with explicit model/provider configuration and caller-supplied local assets. Runtime packages and model weights are separate caller-owned prerequisites; never download or select assets automatically. Verify pinned bytes through one opened descriptor and probe the requested backend in an owned child. Keep cancellation pending until physical child close, drain poisoned queues, handle stdin EPIPE, bound IPC bytes and close owned streams/listeners/timers. Kill only owned processes. Importing either public entry starts no work and never downloads weights.

Object proposals are an explicit caller-owned strategy. Native work closes before model requests; retain packed masks, not full-size rasters for every candidate. Derive boxes and seed overlap from actual nontransparent foreground pixels, never the enclosing rectangle alone. A native quality score is an uncalibrated finite diagnostic that may lie outside [0,1]; never clamp it, use it for semantic selection, or send it to the model. Whole-object box correctness and extraction mask correctness require separate evidence. Do not globally settle or dispose a shared proposal port from one classifier.

Text-image experiments must send zero image parts and use no hidden OCR/semantic/segmentation helper. Allocate the complete request budget before encoding; preserve aliases, source transforms and grid geometry once, without truncation. Losing candidates stay in benchmarks and out of npm dist. Promote one profile only after independent development selection and frozen heldout qualification; an unqualified public profile must reject explicitly. Never choose another candidate from revealed heldout failures.

Implementation edits to source, tests, configuration, and documentation go through Cursor CLI Composer agents under a coordination supervisor. The main orchestrator model is human-selected, must not assume a default main model, and by default performs analysis, research, review, planning, tests, and reviewed Git integration; it never launches, owns, or substitutes for Cursor CLI implementation. Before any implementation dispatch or replan, the main shows the user numbered dependency-ordered waves with roles (main, coordination supervisor, Composer), exact model settings, concrete owned paths, inputs, parallelism/worktree ownership, artifacts outside the repository, checks, and exit criteria, plus a brief plain-language purpose; this is required plan visibility, not repeated approval seeking. Established session authorization is sufficient for scoped implementation, review, fixes, tests, and integration; do not invent permission gates. Every Codex subagent of any role, including coordination and explicitly requested research or review, must be spawned as `gpt-6-luna` with high reasoning and `fork_turns=none` unless the human overrides. Dedicated research or review subagents run only when explicitly requested and remain read-only; otherwise the main performs that work. The main and every spawned Codex subagent read both global rule files under `/root/.cursor/rules/`; the supervisor includes applicable constraints in every Composer task prompt because Cursor does not automatically load home rules. Each coordination supervisor owns every Cursor CLI process it launches (ownership transfer is explicit; the supervisor need not share the main’s OS process), and dispatches Composer using the exact advertised ID `composer-2.5-fast` (“Composer 2.5 Fast”) with no fallback. Before the first dispatch, verify `cursor-agent --version`, `cursor-agent status`, and `cursor-agent models`. Never use Auto, substitute non-Composer implementation for scoped Composer work, or silently fall back to `composer-2.5` or another model family when authentication, quota, access, or availability blocks that exact ID; stop and report the actual blocker. Explicit later owner instructions can change this preference. One supervisor per Cursor process. The Composer executor assigned to a doc or code task edits authorized files itself and must not launch `cursor-agent`, delegate, or recursively dispatch sub-agents. Use at most three concurrent Composer processes globally; parallel Composer work requires separate worktrees with disjoint file ownership, explicit coordination on shared files, merge only after reviewing actual diffs and test output, and global gates on a stable tree. Physical provider dispatches are counted at fetch, independently of logical attempts and receipts. Corpus truth never enters producer payloads. Preserve failed runs, unknown charges and pending/excluded platform checks.

In WSL, confirm `process.platform` and the resolved Node/npm executables before running gates. Windows interop may expose a Windows npm launcher that fails on UNC working directories. Activate an installed Linux Node with its explicit bin path or nvm; do not infer that Linux Node is absent merely from the inherited PATH. Use a native Windows consumer directory only for separately labeled Windows checks.

Path assertions must use the target platform's `node:path` joins/resolvers; do not hardcode POSIX suffixes in cross-platform tests. Keep failed CI receipts and rerun the repaired source on every required platform.

An evaluator must preserve a recipe's real profile/phase identity and validate its own frozen corpus, source, policies and physical receipts. Prefetch validation failures can have logical evidence and zero physical calls; never invent charges or equate these counts. Carry the selected DEV recipe's deadline, scheduling, native limits and task policy into heldout. A changed recipe requires a separately named development comparison and a new freeze.

Historical benchmark `hashCanonical` is SHA-256 over `JSON.stringify`, not a recursively sorted canonical JSON format. Its exact object insertion order is part of frozen identities. Reuse the actual producer's ordered per-variant prompt and policy shapes, and independently reconstruct every candidate/control identity before dispatch. Do not copy a candidate prompt policy into a control, reorder fields through a shared spread, or change the hash algorithm to repair an old receipt. Preserve rejected pre-dispatch drafts and failed runs; correct metadata prospectively.
